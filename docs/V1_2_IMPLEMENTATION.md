# V1.2 角色扮演资料库与 Live2D 陪伴闭环

状态：Live2D 主线已完成自动验收；真人目视发烟统一延期到 V1.3。

## 完成范围

V1.2 在 `main` 完成 Live2D 主线的角色资料库、可信检索、本轮情绪回应边界、可选索引评估、作品社区词库改进和本地数据恢复验证。产品方向是 `neuro-like` 长期陪伴。

按用户要求，本阶段不实现 `gif-version` 的 WebP 标签判定、表现策略与本地小模型专项模板，也不进行真人目视或真实窗口 UI 实测。双版本表现能力验收与 WebP 判定标准统一延期到 V1.3；这些内容不影响 main 的文字聊天、Live2D 显示或本地数据闭环。

## 角色资料与检索

- `CharacterKnowledgeBase` 将身份、性格、经历、关系、情境、说话规则和短句拆成独立记录。
- 每条记录保存字段路径、来源 ID 和 `direct`、`synthesized` 或 `legacy-aggregate` 证据性质。
- SQLite v5 使用独立角色命名空间、外键和事务保存资料正文、来源与证据；不复用用户记忆表。
- 每轮固定保留身份和说话规则，再按关键词取少量相关资料；默认不超过 4 条、2,400 字。
- 资料缺失、版本不一致、JSON 损坏或可选检索失败时回到已验证角色卡，不阻断聊天。
- 保存用户确认的新角色资料时，角色卡和 SQLite 资料使用版本指纹对齐，避免新旧资料混用。

## Live2D 情绪与关系连续性信号

当前实现参考 [my-neuro](https://github.com/morettt/my-neuro) 的长期角色方向，但不复制其代码或整套服务。V1.2 不制造一个无法解释的“总好感度”，而是保持分层：

1. 角色资料决定身份和表达方式；
2. 可信长期记忆提供用户确认过的稳定事实；
3. 最近对话保留眼前语境；
4. 关系连续性规则禁止一次夸奖、辱骂或情绪让亲近程度突然跳变；
5. 本轮明确的低落、喜悦、焦虑或辱骂只生成临时回应策略；
6. 模型返回的结构化情绪和动作由现有 Live2D 表现层校验，失败时回到中性与待机。

普通句子不会被强行标注情绪。本轮信号不会写入长期人格、用户画像或正式记忆；长期事实仍只来自手动记住或通过可信候选流程确认的内容。

`my-neuro` 的记忆说明记录了 MemOS、核心记忆、画像候选、AI 日志、时间信息，以及向量、BM25、关系图和精排的组合；本项目已经采用候选治理、稳定事实与按需召回的思路，但保持 SQLite 关键词为基础路径。`my-neuro` README 将长期情绪状态描述为继续开发的目标，因此本项目也把跨会话持续情绪留作独立后续设计，不在 V1.2 假装已经完成。

## 可选索引结论

固定评测覆盖身份、阿米娅关系、称呼与语气、低落安慰和辱骂边界。当前 38 条凯尔希资料使用关键词检索为 5/5 命中，因此 V1.2 不安装 Embedding 模型，不连接 Qdrant 或 Neo4j。

语义检索接口已经存在，并限制在当前角色的已验证记录内。未知记录、跨角色结果、非法分数或接口异常都会被忽略。详细门槛见 [V1.2 可选资料索引评估](V1_2_OPTIONAL_INDEX_EVALUATION.md)。

## 作品社区词库

- 除词条名与别名外，正文和来源语境也可以参与本地检索；短数字仍使用边界匹配，避免把 `325` 错命中为 `1325`。
- 当前消息会与最近四条已完成对话中的最近相关语境组成最多三条查询，分别检索后使用 RRF 确定性合并；术语和别名的完全命中始终优先。
- 已命中的词条可以沿正文中明确出现的术语或别名继续关联，最多两层、总计不超过三条；没有可靠命中时不注入猜测，也不静默联网。
- 缓存读取会校验版本、作品 ID、条目长度、置信度和来源 URL；损坏缓存直接回到随程序提供的校对词库。
- 只接受 HTTPS 公开来源；自动测试允许本机回环 HTTP。
- 用户点击同步后会按作品名主动搜索社区梗、黑话、术语和别名；没有内置词库的新作品也会使用稳定哈希建立独立本地命名空间。
- 搜索摘要只用于发现候选页面，必须重新读取允许站点的页面正文，并同时确认作品名、术语和社区语境标记后才可缓存；单一来源保持低置信度，至少两个独立页面互证后才提高。
- 通用同步会组合四组搜索，并从梗合集的小标题及正文引号短句中提取候选；短句附近必须明确出现“梗、迷因、二创、童谣、台词”等语境。标点简写和“啦/了”常见变体可作为别名匹配，但普通章节标题不会收录。
- 同步结果报告搜索次数、发现条目数、搜索失败状态、已知来源检查数、确认数、失败来源、社区手册条目数和最终缓存数。
- 所有来源都失败时不写缓存、不覆盖旧数据，并明确告诉用户仍在使用原有本地词库。

## 自动恢复与一致性

角色名称与来源作品共同确定稳定的人格命名空间。切换角色时，对话历史、会话摘要、长期记忆和角色资料随人格一起切换；再次切回同一角色时恢复该角色自己的内容，不读取其他角色的数据。编辑同一角色的描述或语气不会另建空间。

自动测试覆盖：

- 超过 2,000 条消息后的有界保留、关闭数据库后重新打开和跨角色隔离；
- SQLite `integrity_check`；
- 角色资料替换中途失败时整笔事务回滚，旧资料仍完整；
- 可选角色资料索引损坏时返回不可用，但不删除聊天；
- 语义检索故障与纯关键词基线一致；
- 词库缓存损坏和同步来源全部失败时安全回退；
- 社区梗的短词提取、最近语境补全、RRF 稳定排序、两层关联和代词误判过滤；
- 本轮情绪策略随当前消息变化，已确认事实和关系边界保持稳定。

所有测试使用 fake、本机临时数据库和本地 HTTP，不读取真实 API Key。

## V1.3 及后续

- V1.3 只继续 `main` 的 Live2D 表现能力、成熟运行时设计和真人验收；`gif-version` 保持 V1.2 基线；
- WebP 标签判定、表现优先级、恢复时间和本地小模型紧凑模板进入 `gif-version` 后续单独授权的里程碑；
- 真人目视与真实 Electron 窗口实测，包括不同缩放、拖动、长回复和长时间桌面运行；它不再作为 V1.2 的未完成尾项；
- 只有固定评测出现可重复的关键词漏召回后，才重新评估本地 Embedding；
- 只有出现有效多跳关系测试后，才重新评估关系图。

# Genie-TTS 与圣园未花交接记录

更新日期：2026-09-04。本文保留分阶段验证记录；主程序尚未提交、推送或发布，继续补齐 v1.8 全部任务后再发布。

## 已完成

- 四类资源中心增加 Genie 引擎、Genie 基础模型、圣园未花音色，均使用独立安装目标。
- 中文备注：**圣园未花（Mika）／日语音色／《蔚蓝档案》**。卡片及语音设置说明所需三项资源。
- 选择本机 Genie-TTS 时，默认填写受管理的本机地址及 Mika 配置；保存并启用后才准备语音。仍保留用户自行运行 Genie 服务的配置能力。
- Main 管理固定进程，三项安装记录均匹配编译期锚点且必要文件完整才启动。开发路径也不能绕过激活校验。
- 服务只接受固定角色和有长度上限的文本，拒绝文件路径、其他角色、缺失会话凭据和带 Origin 的网页请求。PCM 由 Main 适配器包装为 WAV，流式接收有体积上限。
- 主窗口启动不再等待 TTS 预热；语音状态能返回“正在后台预热”，Renderer 定时更新准备结果且保留尚未保存的设置。
- 原始模型没有量化、转换或改写。OneDrive 中传统 VITS/MoeGoe 音色没有接入。

- `pnpm verify` 全部通过：122 个测试文件、595 项测试，包含 lint、格式、类型检查、生产构建、两个沙箱 Preload 以及 Electron sherpa/SQLite 冒烟检查。日志：`.release/genie-verify.log`。
- 使用独立 Python 3.12.10、Genie-TTS 2.0.2、ONNX Runtime 1.22.1 CPU 完成真实日语合成。

- 独立 HTTP 服务通过两项请求来源/凭据检查、三项非法输入检查，随后正常生成音频。

- 新回归覆盖未激活资源禁止启动、并发启动复用、会话校验、异常就绪响应、停止进程、受限音频流、Genie 准备状态及中文资源说明。

## 本地组件归档

### 句尾气声修复（引擎组件 1.0.1）

- 用户反馈句尾像呛到的气声。原 WAV 的最后约 35 ms 在短暂安静后再次出现声音。
- 定位到固定 Genie 2.0.2 解码器将末尾结束标记替换为普通 `0`，又送入声码器。固定同一份语义序列比较，只排除该占位值后，两段尾部 50 ms 的峰值分别由 15946 降至 1634、2128 降至 5。
- 修正在声码器输入边界进行，保留之前全部语音值，包括正常零值；没有使用定长裁音、能量门限或修改模型权重。重复初始化不会重复剔除，异常协议返回拒绝推理，取消返回保持不变。
- 三项 Python 离线回归通过。引擎 1.0.1 重新归档测量、写入编译期记录，并通过实际下载更新、离线恢复、启动及合成。新 WAV 为 327724 字节、5.12 秒，最后 50 ms 峰值为 2，末采样为 2，接近静音。
- 新试听 `.release/genie-review/mika-installed-tail-fixed.wav`；固定相同语义序列的对比 `.release/genie-review/mika-tail-before.wav` / `mika-tail-fixed.wav`；证据 `probe-tail.json`、`tail-install-result.json`。听感仍请用户试听确认。

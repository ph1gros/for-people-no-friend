# V1.3 成熟方案对照与采用边界

本轮认真对照了 [AIRI](https://github.com/moeru-ai/airi) 与 [SillyTavern](https://github.com/SillyTavern/SillyTavern)。目标不是把两个大项目塞进桌宠，而是把已经成熟、适合 For People No Friend Live2D 主线的分层方法用自己的代码实现。

## 许可证与范围

- AIRI 使用 MIT 许可证，可以参考其架构和实现方式；本项目仍按自己的依赖、窗口结构和安全边界实现。
- SillyTavern 使用 AGPL-3.0。这里只采用角色卡分层、提示词编排、示例对话预算和 World Info 检索规则等设计思想，不复制其源码或预设正文。
- AIRI 的 Agent、插件、工具、语音与游戏控制，以及 SillyTavern 的脚本/扩展生态，都不属于 V1.3；其中适合项目方向的能力已进入后续独立里程碑，不会借“参考”绕过权限设计。

## 已采用

| 成熟做法                                                           | 本项目实现                                                                                            |
| ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| AIRI：先把模型等比适配画布，再叠加模型自己的位置和缩放             | `model.json` 新增可选 `presentation`；自动适配、角色构图和用户窗口缩放各自独立                        |
| AIRI：动作、表情、眨眼等通道明确交接，不让旧状态残留               | 保留 Live2D Motion/Expression 原生分工；无 Expression 的模型可声明情绪 Motion，动作结束后恢复最新状态 |
| AIRI：运行上下文使用稳定、扁平的结构，避免弱模型模仿复杂标记       | 系统提示按“稳定角色核心、当前会话上下文、回复边界”分段，不使用可被照抄的 XML 包装                     |
| SillyTavern：角色核心常驻，示例对话按上下文预算逐块加入            | 身份、性格、说话方式常驻；最多选四条情境匹配示例，并受独立字符预算限制                                |
| SillyTavern：World Info 以关键词和预算为基础，向量检索只是可选补充 | 角色资料继续关键词优先、按人格命名空间隔离；可选语义检索失败时回到关键词，不影响聊天                  |
| SillyTavern：示例对话与真实历史必须有清晰边界                      | 提示中明确示例不是已经发生的对话，只学习态度和语言节奏                                                |
| 两者：生成失败与可选子系统失败不能拖垮基本对话                     | 表现、语义检索和联网资料整理都保留安全回退；基础文字聊天不依赖它们                                    |

## 保留但不照搬

- AIRI 的完整参数插件流水线适合更大的舞台系统。当前先保持“模型 Motion → 自动眨眼 → 模型永久参数”的明确顺序；等凯尔希模型补齐 Expression 映射并完成人工目视，再决定是否需要更细的参数所有权层。
- SillyTavern 支持非常复杂的递归 World Info、概率组和脚本触发。本项目首要目标是可预测和可追溯，因此继续限制检索条数与字符预算，不加入无限递归、概率激活或自动脚本。
- Character Card V3 的首条消息、备选开场和聊天分支很适合聊天前端；桌宠会延续现有会话，V1.3 不为了字段齐全添加没有运行用途的配置。
- Embedding、向量数据库和图数据库继续只是可选评估接口；它们不进入用户长期记忆，也不是基础聊天依赖。

## 已进入计划的下一批

- V1.3：模型能力报告、上下文注册表、生成生命周期保护、提示词组成检查、短期 Character Note、作品资料持续/冷却和 Unicode 字符簇流式显示。
- V1.4：版本化角色包、本版本内部角色库、导入导出安全检查、角色调试视图、提供商能力描述和本地/远端模型协作。
- V2 及以后：语音和口型、高级记忆索引、受控 Agent/插件、只读视觉与其他渲染器分别进入独立里程碑，并各自重新确认权限。

## 后续验收

- 用真实凯尔希模型确认 `presentation` 微调不会破坏透明边界、拖动区域或 Windows 缩放。
- 为模型真实存在的 Expression Id 补映射后，检查情绪表情与 Motion 同时运行、清除表情和动作恢复。
- 固定输入检查：角色不替用户行动、示例不会被当成历史复读、作品资料只在命中时进入预算。

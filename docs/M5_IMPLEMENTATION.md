# M5 长期记忆

## 范围

M5 在 M4 文字对话之上增加本机、透明、可管理的三层记忆：

- 最近 20 条完整消息作为短期上下文；
- 较早对话压缩为单会话摘要；
- 用户明确保存或后台保守提取的长期记忆；
- SQLite 本地存储、M4 JSON 历史一次性迁移、导出和一致性备份；
- “记住/忘掉”、自动记忆开关、分类查看、来源查看、修改、彻底删除和清空；
- 关键词检索、偏好冲突替换、过期和失败降级。

M5 不包含向量数据库、Embedding、Neo4j、云同步、多角色共享策略、多个会话、语音、主动对话、Agent、MCP、工具调用或桌面控制。Anthropic、OpenAI Compatible 和 Ollama/本地兼容接口继续共用统一模型路由，没有把记忆绑定到单一厂商。

角色本身的作品/游戏来源、正式名与别名、身份、称呼规则、性格特征、关系、背景设定和口癖属于角色卡，不属于用户长期记忆。M5 继续允许用户通过角色简介和人格提示词手动维护这些内容，但不新增联网角色搜索。未来若实现联网补全，应使用独立的结构化角色资料与来源证据（URL、抓取时间、选用状态），先展示候选并由用户确认，不能让网页或模型结果自动覆盖稳定人格。

## 数据与迁移

Main 在 Electron `userData` 中创建 `deskpet.v1.sqlite`，启用 foreign keys、WAL 和 `synchronous=NORMAL`。Schema 版本保存在 `PRAGMA user_version`，当前包含：

- `messages`：保留 M4 的正文、状态、Provider、模型、情绪、动作和 token 元数据；
- `session_summaries`：摘要正文、覆盖到的消息 ID 和更新时间；
- `memories`：命名空间、类型、稳定键、正文、重要度、置信度、来源、时效和状态；
- `memories_fts`：仅为当前有效记忆建立 FTS5 索引；
- `app_metadata`：自动记忆开关、提取水位和迁移标记。

旧版 `conversation.v1.json` 会先做完整结构校验，仅在 SQLite 消息表为空时导入一次。原文件不会删除，导入标记避免重复写入。数据库最多保留 2,000 条当前单会话消息，界面仍只读取最近 100 条。

## 三层上下文

每次回复前，Main 按固定边界组装：人格、会话摘要、与当前消息相关的长期记忆、最近最多 20 条消息。摘要与长期记忆只进入 system context，不混成聊天消息；提示明确规定若记忆和用户当前说法冲突，以当前说法为准。

长期记忆最多检索 5 条（底层硬上限 8 条），上下文总长度最多 6,000 字符。第一版不加载 Embedding；相关度由关键词匹配、重要度、最近确认和最近使用共同计算。检索不到或 SQLite/记忆服务异常时传入空记忆，正常聊天不会被阻断。

## 写入、冲突与隐私

用户可以直接说“记住：……”或“忘掉：……”。明确记忆不调用额外模型，立即以 `manual` 来源保存；同一稳定键的新事实会把旧版本标为 `superseded`。自动提取默认关闭，每累计约 10 轮完整对话在回复后排队运行一次，每批最多写入 3 条，并要求最低重要度和置信度。手动记忆不会被较弱的自动候选覆盖。

记忆类型限定为偏好、人物关系、事件、计划和稳定事实。代码会拒绝密码、API Key、私钥和银行卡样式内容；自动候选还要经过长度、类型、数值范围和 JSON 结构校验。模型只看到当前提取批次，不会收到整个数据库。

“删除”“忘掉”和“清空”不是单纯隐藏：匹配的当前版本和被替代旧版本会清空正文与稳定键、解绑来源消息、删除 FTS 索引，再留下不含原内容的 `deleted` 墓碑。清空记忆不会清空聊天历史；若原话仍在聊天历史中，用户可另行清空历史。已有外部 JSON 导出或 SQLite 备份不可能被应用远程追回。

## 摘要与后台任务

摘要始终保留最近 20 条消息不压缩。第一次在有至少 10 条可压缩旧消息时生成，之后每增加 20 条旧消息再更新；边界会回退到完整用户轮次。摘要带覆盖消息 ID，只有结果确实比原文与旧摘要更短时才写入。

摘要和自动提取使用用户已选择的同一个 Provider/模型配置，通过统一 `ModelRuntime` 执行，不静默切换云服务。两类任务在回复完成后串行排队，应用退出会取消任务；解析、网络或模型错误只跳过本轮维护。停止生成和失败回复不会触发记忆维护。

## 用户界面与安全边界

顶部新增“记忆”抽屉，提供自动记忆开关、类型筛选、来源摘要、编辑、彻底忘掉、JSON 导出、SQLite 备份和全部清空。清空需要二次确认。M2/M4 已确认的桌宠视觉边框、65%～150% 缩放和专用拖动区域保持不变。

Renderer 只能调用 Preload 暴露的具体白名单方法。Main 对布尔值、记忆 ID、类型、正文长度、重要度、置信度和过期时间再次校验，并验证 IPC sender 必须是当前桌宠窗口的 main frame。Renderer 不能传入任意导出路径；JSON 和 SQLite 目标均由 Main 打开的原生保存对话框选择。API Key 仍只在 Main 通过 `safeStorage` 管理。

## 官方依据

- [Node.js `node:sqlite`](https://nodejs.org/api/sqlite.html)：`DatabaseSync`、参数绑定与 SQLite backup API；
- [Electron IPC](https://www.electronjs.org/docs/latest/tutorial/ipc)：Main/Preload/Renderer 的请求边界；
- [Electron Security](https://www.electronjs.org/docs/latest/tutorial/security)：context isolation、sandbox、sender 校验和最小化暴露；
- [Electron `dialog`](https://www.electronjs.org/docs/latest/api/dialog)：由 Main 选择导出和备份目标；
- [Anthropic Structured Outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs) 与 [OpenAI Structured Outputs](https://platform.openai.com/docs/guides/structured-outputs)：确认原生结构化能力依赖具体模型；M5 延续本地严格解析，不对所有兼容端点作错误假设。

## 测试与验证

自动测试只使用 fake 模型事件、本地临时 SQLite 和既有的 `127.0.0.1` fake HTTP，不读取、请求或记录真实 API Key。覆盖：

- M4 JSON 历史一次迁移、SQLite schema、摘要和一致性备份；
- 显式记住/忘掉不调用模型；
- 自动提取批次、阈值、数量、敏感信息拒绝和解析失败；
- 去重、手动优先、偏好冲突、过期、检索和上下文注入；
- 当前及被替代版本的内容擦除、清空和 FTS 移除；
- 所有记忆 IPC 参数、sender 和 Preload 白名单；
- M0 至 M4 的窗口、Live2D、Provider、密钥、缩放、拖动和对话回归。

本地完整验证：

```powershell
pnpm verify
```

Windows CI 使用 Node 24 与 pnpm 锁文件运行同一命令。`smoke:preload` 继续确认沙箱 Preload 是单文件 Context Bridge bundle。测试和构建不会连接真实模型。

## 已知限制

- 当前仍是单角色、单会话；数据库已使用角色记忆命名空间，为未来扩展留出边界。
- 中文 FTS5 分词能力有限，因此 M5 检索同时使用归一化关键词与汉字二元片段；语义向量检索不在范围内。
- 自动提取质量取决于用户选择的模型，默认关闭且所有候选仍经过本地规则过滤。
- M5 不增加模型能力发现，也不为摘要或提取自动选择更便宜的其他云模型。
- M2 的 Windows 跨窗口全屏鼠标跟随遗留未改变。

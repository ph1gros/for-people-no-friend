# V1.4 角色包、混合记忆与模型协作计划

V1.4 解决三件事：角色怎样完整、可追溯地带走，短期与长期记忆怎样可靠协作，以及本地小模型和远端强模型怎样各做擅长的工作。它不是语音版本，也不是 Agent 版本。

当前 V1.4 已完成可运行实现：版本化 ZIP 角色包的预览、确认导入、替换回滚与脱敏导出；角色库和角色命名空间切换；带冷却与原因说明的上下文情境示例；模型能力描述与经用户授权的本地/远端任务路由；关键词、本机向量、关系、重要度和时间融合召回；以及可选 Qdrant / Neo4j 连接和界面调试视图。外部索引默认关闭，连接失败不会阻断基础聊天或关键词检索。

实现边界：本机向量使用固定、无需下载模型的文本特征嵌入，适合补充候选而不替代关键词；Qdrant 只接收向量、随机记忆 ID 和角色命名空间，Neo4j 只接收关系词、类型和 ID，SQLite 仍保存唯一可查看、修改、导出和删除的正文。普通聊天不会因模型协作设置而自动换提供商。

## 角色包

一个角色包至少包含：

- 版本、角色 ID、显示名称和独立命名空间；
- 身份、性格、背景、关系、称呼、说话方式和情境示例；
- 每个字段的来源、取得日期和人工修改状态；
- 作品词库的引用或可公开分发条目；
- Live2D 模型清单、动作/表情映射、构图参数和素材署名；
- 应用最低兼容版本及安全迁移信息。

默认排除聊天历史、摘要、用户长期记忆、联网缓存中的私人内容、API Key 和提供商密钥。需要导出用户资料时必须使用另一条明确流程，不能借角色包顺手带走。

## 模型协作

- 普通聊天优先使用用户当前选择的模型，不在后台偷偷换提供商。
- 用户启用“复杂整理可使用远端模型”后，角色资料整理、来源交叉核验和冲突候选可以交给已配置的远端提供商。
- 每个提供商记录能力而不是只记录名字：是否支持流式、结构化 JSON、取消、模型列表和较长上下文。
- 路由前显示任务类别和数据范围；失败时回到当前模型、关键词结果或人工填写，不让角色无法聊天。
- 测试只使用 fake provider 和本地 HTTP，不读取真实 API Key。

## 混合记忆

- 基础层始终是 SQLite 正文、来源证据、确认状态、冲突与删除规则。
- 短期层保留最近完整轮次、带覆盖位置的摘要、当前场景和有限持续的情绪，不与长期事实混存。
- Live2D 与 GIF 都增加核心事实、事件回忆、候选画像和按日摘要；GIF 默认只注入更少片段，Live2D 可提供更丰富片段，但两边使用相同的确认、冲突、来源和删除规则。
- 本地 Embedding 先通过适配器和固定评测接入；关键词结果始终保留，语义结果只能补充候选。
- Qdrant 与 Neo4j 都是可选外部索引。数据库正文仍可在不启动它们时完整查看、修改、导出与删除。
- 召回结果显示关键词、语义、关系、时间或重要度等命中理由；低证据候选不能静默变成用户画像。

## 验收

- 同一角色包导出再导入后，公开角色资料、来源和表现映射一致。
- 包内路径无法逃出目标目录，远程脚本和未知可执行文件不会被加载。
- 两个角色的资料、历史、记忆、作品词库和素材完全隔离。
- 本地与远端假模型可以按授权路由；远端超时、返回坏 JSON 或断线时安全回退。
- 调试视图能说明本轮用了什么资料、为什么使用、占用多少预算以及发生了什么回退。
- Embedding、Qdrant、Neo4j 任一缺失或损坏时，关键词检索、基础聊天和人工记忆管理继续可用。

自动验收使用 fake、临时目录和本机 HTTP 服务，不读取真实 API Key。角色包解压前检查中央目录、压缩/解压体积、条目数、加密、Zip64、路径穿越和危险扩展名；解压后再次验证清单、远程引用、未声明资源和每项 SHA-256。Renderer 只拿短期预览 ID，确认时由 Main 重新验证并原子写入。

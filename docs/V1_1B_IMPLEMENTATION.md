# V1.1b 记忆整理

V1.1b 接在 V1.1a 的“先候选、后生效”之后，解决候选内容不够准确、相似候选堆叠和时间信息不好修正的问题。它继续使用现有 SQLite 表与关键词检索，不引入新的数据库服务。

## 用户能做什么

- 在确认前修改候选的分类、正文、重要度和置信度。
- 为事件和计划设置或清除有效期；已确认记忆也使用同一套时间编辑方式。
- 将稳定键相同的候选合并到选定目标；目标正文不被另一条静默覆盖，来源证据会去重合并。
- 遇到旧记忆冲突时，选择“用新记忆替换旧记忆”或“新旧两条都保留”。如果需要把两种说法整理成一句，可以先编辑候选，再选择替换。

## 数据与安全边界

- V1.1b 不新增 schema 版本，沿用 `memory_candidates`、`memory_candidate_evidence` 和 `expires_at`。
- 候选修改会重新派生稳定键、过滤敏感内容，并重新计算冲突和人工复核原因。
- 合并只允许当前角色命名空间内、仍处于待确认状态且稳定键与分类都相同的两条候选。
- 合并在一个 SQLite 事务中移动并去重证据，再擦除被合并候选的正文和原证据，只保留不可逆指纹以免它重复排队；失败会整体回滚。
- 冲突决策由 Renderer 通过固定枚举传入，Main 再次校验；未知值、伪造 ID 和跨角色操作会被拒绝。
- V1.1b 不加入向量数据库、Embedding、Python 服务、语音、Agent、MCP、屏幕观察或桌面控制。

## 验证

自动测试覆盖候选编辑、有效期保存与清除、同键证据合并、跨命名空间拒绝、冲突替换与两条保留，以及新增 IPC 输入的边界校验。完整验证命令为：

```powershell
pnpm verify
```

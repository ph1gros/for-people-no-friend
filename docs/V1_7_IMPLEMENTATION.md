# V1.7 当前实施与安全边界

本文记录 V1.7 已实现的功能、可选资源边界和发布验收。源码与本地便携包完成不等于已经创建 GitHub Release；标签和公开发布仍是独立操作。

## 1. 可扩展 TTS

设置页现在提供四种状态：关闭、OpenAI 兼容 TTS、Genie-TTS、Fish Audio。

- OpenAI 兼容 TTS 保留 V1.6 行为，可连接本机或 HTTPS 在线接口。远端必须使用 HTTPS，本机 HTTP 只允许 localhost、127.0.0.1 或 ::1。
- 语音默认关闭，并按安装包实际资源决定初始配置。公开包没有伊蕾娜权重时，OpenAI 兼容项显示为通用“OpenAI 兼容 TTS（本机或在线）”，模型 ID 与音色 ID 均不预填；旧版遗留但从未启用的伊蕾娜占位配置也会清除。只有私人或未来已获授权的完整包确实检测到音色文件时，才显示“本机 Style-Bert-VITS2”，并使用模型 `style-bert-vits2`、音色 `ireina`、语言 `ja-JP` 的伊蕾娜预设。所有已启用的 TTS 都直接显示语音模型 ID、音色 ID 与“确认”按钮；伊蕾娜只是预填值，不使用专用摘要卡。确认与右上角保存都会在按钮上显示处理结果，最终仍由右上角“保存”写入设置。
- Genie-TTS 是独立本机提供方，只允许回环 HTTP，并调用 `/tts`。角色必须先由 Genie-TTS 加载并设置参考音频；FPNF 使用填写的音色 ID 作为 `character_name`。Genie 上游把 32 kHz、16-bit、单声道裸 PCM 标记为 `audio/wav`，因此 Main 会先补成标准 WAV 再交给 Renderer。当前支持的是 Genie-TTS 上游声明的 GPT-SoVITS V2/V2ProPlus ONNX，不把 V4 或传统 VITS 权重伪装成兼容模型。
- Fish Audio 使用固定 `https://api.fish.audio/v1/tts`，模型只允许 `s1` 或 `s2-pro`，音色字段是 `reference_id`，输出只允许 WAV、MP3、Opus。API Key 按提供方分别存入 Main Process 的安全存储，不进入 Renderer、角色包、日志或测试。
- 输出语言提供日语 `ja-JP`、中文 `zh-CN`、英语 `en-US` 三个常用选项；其他语言可选择“自定义”并填写语言代码。读取旧配置时，非这三种代码会自动保留在自定义输入框中。
- 日语朗读转换只在输出语言为日语时运行。英语、中文及其他语言不会再被强制转换成日语。

所有提供方响应都有超时、重定向拒绝、最大 16 MiB、音频 MIME 和文件签名检查。自动化测试只使用 mock 或本机 HTTP；没有读取或调用真实 API Key。

基础包只携带受控服务入口，不携带 Python、本地 TTS/ASR 依赖、日语 BERT、SenseVoiceSmall 或伊蕾娜音色权重。Python、日语 BERT 和 SenseVoiceSmall 组成独立的公开本地语音运行组件；伊蕾娜音色仍是另一个私有非商业可选包。安装运行组件与有权使用的音色后，服务用 `/ready` 做真实模型预热，不会把仅能返回 `/health` 的进程误判为可朗读。DirectML 在模型加载或实际推理中发生设备移除时，会释放失效会话并只用 CPU 重新加载；Main 只记录有界的提供方状态码，不吞掉错误，也不写入合成文字或本机路径。本机 ASR 只有在回环服务实际可连接时才显示为可用；若 9880 等配置端口没有服务，会明确显示“未安装或未启动”，而不是让录音完成后必然失败。

Main Process 只从明确列出的安装目录相对位置选择语音运行时；可选组件直接合并到 `<FPNF>/resources`，不记录开发电脑的绝对路径。Python、模型和维护中的服务模块可以位于不同的受控目录，但所有真实路径、必需文件和符号链接都会在启动前重新验证。只有安装了本地语音运行组件、可选音色且 Style-Bert-VITS2 `/ready` 完成真实预热后，语音输出才标记为可用。中文语音输入开启且指向本机时，会先尝试启动固定的 SenseVoiceSmall 服务，再以 `/ready` 和 `/health` 结果决定完全/精准监听是否可用；优先 CUDA，失败后回退 CPU。基础包不从开发者私人 `data` 目录读取资源。

精准麦克风模式不再固定称呼“小猫”。默认使用当前激活角色卡的名称；切换角色选项卡后，下一句语音立即按新角色名识别。用户也可以选择“自定义称呼”并填写最长 32 个字符的名称。旧设置自动迁移为“跟随当前角色名称”；空白、自定义纯标点、控制字符和超长输入会在 Main Process 再次拒绝。

## 2. 私人传统 VITS / Piper 实验

下载 ZIP 中 15 套模型均为传统 MoeGoe/VITS 结构。代表样本只有 `G_latest.pth` 和 `moegoe_config.json`，配置使用 `zh_ja_mixture_cleaners`、22050 Hz 和 MoeGoe symbols。它们不是 Piper 的 ONNX + JSON voice，不能直接交给 Piper。

私人检查只在 Git 忽略的 `data/voice-clone-experiments/legacy-vits-piper-check` 中抽取一套代表模型。检查没有调用 `torch.load`，因为 PyTorch checkpoint 内的 pickle 元数据在不可信情况下可能执行代码。其余模型没有重复复制。

可行路线：使用匹配的 MoeGoe/VITS 本机服务试听；或使用拥有权利的原始录音和标注重新训练 Piper。专门重建网络再导出 ONNX 只能作为隔离研究，不保证与 Piper 配置或音质兼容。

## 3. VTube Studio 与 ViewerEX

VTube Studio 在原有自动语义匹配之外增加人工映射：读取当前模型清单后，可逐个预览表情，再把准确的 `.exp3.json` 映射到 neutral、happy、sad、angry、surprised、shy、playful。保存后优先使用人工映射，未映射项才回退到名称猜测。这适合 ATRI 一类表情文件只有编号、没有语义名称的模型。

读取按钮每次都会刷新当前模型，而不是一直返回旧的内存清单；只有 `modelLoaded=true` 且模型 ID 非空才显示读取成功。表情发送结果会区分未授权、模型未加载、连接失败和映射缺失，因此“惊讶”没有匹配项时会提示先预览并保存映射，不再误报为未授权。只修改表情映射或鼠标追踪不会断开已有 API 会话。

普通用户只需点击“连接 VTube Studio”。Main Process 先快速尝试已保存或默认的本机回环端口，能够连接就立即请求官方插件授权；只有该端口不可用时，才监听 VTube Studio 官方每两秒发送一次的 UDP 状态广播并尝试它报告的实际端口。这样即使 Windows 防火墙或网络环境收不到广播，默认 8001 可用时也不会让自动连接失败。广播只读取接口是否开启和实际端口，不保留实例 ID 或窗口标题；只接受本机网络接口来源、限制报文大小并严格验证结构，不做端口扫描，也不读取或改写 VTube Studio 配置。若 VTube Studio 尚未开启“允许插件 API 访问”，WebSocket 服务本身不存在，FPNF 无法代替用户打开该开关；能收到广播时界面明确显示该开关说明，收不到广播时则合并提示“确认已启动并打开插件 API”。手动端口降级到折叠的“连接故障排查”，正常流程无需填写。

全新环境未配置 AI 对话模型时，右上“保存”仍会保存语音、语音输入、角色显示、ViewerEX、VTube Studio 和布局等独立设置，只提示聊天模型尚未配置；只有“测试 AI 连接”和真正发送聊天时才要求模型名称。点击“连接 VTube Studio”会自动启用该显示适配，授权并成功读取模型后直接切换角色显示，不再产生“令牌已授权但角色显示仍关闭”的死状态。

Spout2 接收器现已重编译为优先使用 Windows 高性能显卡，并启用 Spout 自动兼容模式，适配 VTube Studio 在独显、桌宠误跑核显的双显卡情况。接收器会向 Main 报告发送源未开启、连续收不到帧或已经收到画面，即使设置页打开也会继续完成这项预检；设置页据此分别提示开启 Spout2 或让两端使用同一块高性能显卡，不再用隐藏的 1×1 窗口静默表示失败。VTube Studio 自带 Spout2 输出，FPNF 也自带所需接收器，使用桌宠不需要另外下载 OBS 的 Spout2 插件；只有 VTube Studio 内部的 Spout2 输出开关仍需用户本人打开，因为官方 Plugin API 没有修改该设置的接口。

V1.7 基础包不带任何身份卡或模型，新安装只建立中性的“桌宠”占位资料且角色显示默认关闭。“安装模型”只在 Main Process 实际检查到安装包内存在安全的 `.model3.json` 模型时显示；基础包不会给出一个必然失败的随包安装按钮。身份卡、VTube Studio 模型和语音权重分别配置，互不冒充。

可选资源使用安装目录相对结构：运行时通过 Electron 的 `process.resourcesPath` 定位 `<应用目录>/resources`，再读取 `voice-runtime/voice/<音色 ID>`，不会记录开发电脑的绝对路径。VTube Studio 本身是另一款程序，因此模型目标必须在每台电脑上使用其本机 `VTube Studio_Data/StreamingAssets/Live2DModels`；这一步不是 FPNF 包内路径，也不能写死为某台电脑的盘符。身份卡使用应用内导入，不要求接收者寻找用户数据目录。

映射只接受当前设置中有界的情绪键和安全的单文件名，不允许路径分隔符、控制字符或非 `.exp3.json` 文件。Renderer 不能自行向 VTube Studio 发送任意请求。

ViewerEX 继续使用 V1.6 的 ExAPI 本机端口范围、模型索引、气泡、状态动作、情绪表情和角色动作映射；当前实现已有 Main 重验、映射草稿解析和本机协议测试。

## 4. 角色套装迁移

沿用 V1.6 已完成的 `.fpnf-character.zip`：导入前预览角色、素材数量、授权说明和冲突，确认后才写入；归档限制压缩体积、展开体积、单文件体积、文件数量和路径，逐项校验 SHA-256。导出不包含聊天、长期记忆、API Key、VTube Studio 授权令牌或本机绝对路径。

V1.7 暂不把私人音色权重自动塞入角色包。大模型和语音权重继续采用可选组件或用户管理路径，避免基础包膨胀，也避免把尚未确认再分发权的素材带入公开包。

## 5. 工作模式动作

工作模式现在可以直接完成普通问答；遇到时效资料、来源核对或用户明确要求联网时，再使用有界网页搜索和公开 HTTPS 网页读取。代码任务可以列文件、按内容搜索、读取文件、创建单层目录、写入小文件和精确替换文字。单项任务的安全步骤上限从 8 提高到 16，适合完成“查找—阅读—修改—验证”的小型闭环，但仍不会无限自主运行。

工作模式只增加能力，不切换人格。工具参数保持准确和中性，最终回答仍必须采用当前角色卡规定的身份、用户称呼、性格、观点、措辞、句子节奏与情境反应；不能退回通用助手或客服语气。角色表达也不能改变文件内容、代码、检查结果或网页来源等事实。

所有文件内容和网页内容都视为不可信资料。Main Process 会重新解析真实路径并检查体积、文件类型和工作区范围；内容搜索跳过符号链接、依赖目录、构建输出、二进制和过大文件。精确替换默认只允许唯一匹配，多处替换必须明确指定。选择工作区即授予区内文件操作范围权限；访问区外真实路径必须逐次显示操作类型和实际目标并等待确认，拒绝后不执行。

会改变系统状态或执行代码的工具包括：

- `list_files`、`search_files`、`read_file`、`write_file`、`replace_in_file`、`create_directory`：工作区内直接执行；工作区外逐次确认。写文件使用同目录临时文件后原子替换，拒绝符号链接和非普通文件，读取与搜索继续执行体积和二进制限制。
- `run_project_check`：只接受 test、lint、typecheck、build 四个固定名称，并且 package.json 必须真实声明对应脚本。批准框会明确说明项目脚本将执行工作区代码；不接受模型提供的命令、参数或 shell 内容。在 Windows 上仅通过固定的 `cmd.exe /d /s /c <包管理器> run <固定检查名>` 入口启动 `.cmd` 包管理器，所有片段都来自程序白名单；子进程也不会继承 API Key 等一般进程环境。

- `open_file`：工作区内常见文档、图片、音视频和文件夹直接打开；工作区外目标或程序、脚本、快捷方式与未知扩展会显示规范化后的真实路径和执行风险，确认后才交给系统默认应用。
- `media_control`：只允许 play-pause、next、previous 三个固定命令。启用“听歌控制”小组件即授予这三项范围权限，不再逐次确认；Main 优先使用 Windows 当前或正在播放的 GSMTC 媒体会话，不再因另一台电脑上的网易云版本发布了不同来源 ID 而丢弃曲名或跳过控制。状态脚本在序列化前逐字段限长，总响应上限为 64 KiB，避免多个浏览器和媒体会话把整次查询挤爆；没有可调用会话时才回退固定系统媒体键。Renderer 仍不能提交程序名、命令行、窗口标题或任意按键，小组件关闭时命令不可用。

模型不能用文字声称扩大工作区或小组件范围。需要逐次确认的工作区外文件、脚本和项目检查在拒绝后不得重复请求。工作模式仍不提供任意终端、任意媒体命令、未经确认的工作区外访问或绕过批准的后台动作。

对话输入框改为三行起步，可自动增高到 240 px；单条文字上限由 8,000 提高到 16,000 字符，便于粘贴较长需求和代码片段。

设置页的状态与“保存”按钮已移到右上角，顶部整条都可拖动窗口，按钮区域仍保持可点击。透明置顶窗口的最外沿始终绘制边框，让实际会拦截鼠标的窗口范围清楚可见。

## 6. 发布前真实验收

仍需用户在清醒时提供或确认以下条件：

1. 使用有权使用的 GPT-SoVITS V2/V2ProPlus ONNX 角色，在本机 Genie-TTS 中完成加载、参考音频和实际首段延迟测试。
2. 用户自行填写 Fish Audio Key 和有权使用的 reference_id，明确确认文字上传后做一次真实在线生成；测试仓库不会保存该 Key。
3. 在 VTube Studio 实际加载 ATRI，逐个预览并保存情绪映射，检查表情恢复、待机参数和追踪冲突。
4. 在双显卡测试电脑上让 VTube Studio 开启 Spout2，确认桌宠模型画面不再停留在隐藏的 1×1 窗口，并核对设置页能显示发送源或显卡错误。
5. 分别在 9880 没有服务和真实 SenseVoice 服务已启动时检查语音输入状态；再验证 DirectML 失败后 CPU 能生成并播放首句。
6. 在 ViewerEX 中实际启动目标模型，核对动作组、表情编号和气泡。
7. 对角色包做一台干净 Windows 环境上的导出、导入、冲突替换和缺少可选语音服务测试。

# V1.9 计划

开发基线为 [v1.8.3 交付记录](V1_8_3_DELIVERY.md)。本页记录下一阶段范围与验收条件，不表示这些功能已经接入或通过验收。

## AstraTTS：先解决流式连续性

[AstraTTS](https://github.com/Blackwood416/AstraTTS) 的模型转换与流式能力安排在 V1.9。现有生产语音引擎、资源目录及 v1.8.3 基础包不包含该试验。

隔离试验已观察到流式提前输出音频；用户对同一句开头的对比试听确认，默认流式比完整生成的卡顿更明显。足够的音频供给速度不能证明听感连续。当前证据提示分块拼接及句间补静音需要进一步区分，不能把词内卡顿仅归因于文本或网络，也不能将假设当成已确认的唯一根因。

下一步按以下顺序验证：

1. 核对现有 Genie 音色与转换工具的格式、输入输出及许可；先验证一个已获授权的音色能否转换，不批量迁移资源。
2. 同音色、同文本对比完整生成与不同分块大小，记录首个有效发声、分块边界、缓冲耗尽、尾部结束及用户试听结果。
3. 复现开头词内卡顿，区分模型重复生成的差异、拼接不连续、句间静音和播放器供给问题；修复后以同一组样本回归。
4. 只有连续听感、取消后恢复、内存占用及长短句验证满足要求后，再决定正式引擎接入和组件分发方案。转换成功与可以发布是不同的验收项。

本地试验音频与日志保存在忽略目录，不发布模型、私人角色资产或试验运行环境。

## 情绪模型候选

[emotion-engine](https://github.com/fenghua2006/emotion-engine) 的十通道模型保留为候选方向。后续先与现有情绪和关系逻辑比较，再确定状态演化与现有表情映射的边界；十个内部通道不等于必须添加十套表情素材。尚未承诺整套上游服务接入。

## 桌面与试听验收

人工验收统一维护于 [V1.9 人工验收清单](V1_9_VISUAL_ACCEPTANCE.md)。静态图边框与投影的外观方案仍需设计决定，不能因旧任务清单而自行删改。自动检查通过不替代实际多屏、DPI、无障碍与听感验收。

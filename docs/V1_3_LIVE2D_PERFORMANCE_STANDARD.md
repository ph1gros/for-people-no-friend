# V1.3 Live2D 表现标准

状态：首批 Live2D 基础已实现；main 的真人 UI 目视验收仍待完成。GIF Version 也在 V1.3 升级角色扮演、短期记忆和表现规则，但使用自己的 WebP 调度文档与实现。

## 表现语义

Live2D 使用以下表现含义：

- `idle`：没有生成任务和一次性动作时的稳定回退；
- `thinking`：请求已经发出、正文尚未开始返回；
- `talking`：正在显示回复正文；
- `emotion`：最终回复经过校验后的短期情绪；
- `action`：模型从当前角色允许列表中选择的一次性动作。

运动通道的优先级为“一次性动作 > thinking/talking > 情绪动作 > idle”。Live2D 的 Expression 可以与 Motion 同时存在，不需要把参数化表情降级成单段动画。一次性动作结束后恢复最新状态和仍然有效的短期情绪，而不是恢复动作开始前的旧快照。

## 时间与冷却

- Live2D 一次性 Motion 最长等待 `12 秒`；驱动报错或超时视为未播放，并恢复最新状态。
- 同一个一次性动作从入队起冷却 `1.2 秒`；不同动作仍按 FIFO 执行。
- Live2D 当前恢复延迟为 `0`，避免动作结束后留下空帧。
- 冷却只抑制重复装饰动作，不能阻止 thinking、talking、idle 或文字聊天。
- 模型没有 Expression 时可以显式提供 `emotionActions`；回复已经选择动作时以该动作为准，否则播放对应的短情绪 Motion。

## 情绪连续性

- 只看当前人格最近四条已完成记录，不读取其他人格历史。
- 当前消息有明确低落、喜悦、焦虑或辱骂线索时，最终可见情绪服从当前语义。
- 当前没有新线索且模型返回 `neutral` 时，可以沿用窗口内最近的明确情绪。
- 模型返回新的非中性情绪时，旧的延续情绪不再覆盖它。
- 离开四条窗口后自然失效；短期情绪不写入长期记忆、关系等级或用户画像。

## 缺失与失败回退

- 未列入当前角色允许列表的动作直接忽略；
- 缺失状态 Motion 时回到 `idle`；
- 缺失或无法应用表情时回到 `neutral`；
- 一次性动作异常、超时或资源解码失败时恢复当前状态；
- 任何表现故障都不能阻断文字回复。

## 模型构图与角色扮演

- 模型先等比适配当前画布，再应用清单中的 `presentation.scale/offsetX/offsetY`；用户调整桌宠窗口尺寸是更外层的设置，两者不能互相覆盖。
- 稳定身份、性格和说话方式常驻；背景、关系、作品词条和情境示例按当前问题与预算加入。
- 情境示例不是聊天历史，最多选四条；角色只回应当前这一轮，不替用户补写行动或心理活动。
- 详细采用依据与暂缓内容见 [V1.3 成熟方案对照](V1_3_AIRI_SILLYTAVERN_ADOPTION.md)。

## 自动验收

- 明确辱骂配上 `angry`，低落配上 `sad`，喜悦配上 `happy`；
- 中性下一轮可以短暂延续，新的明确情绪会覆盖旧情绪，四条窗口外失效；
- 动作 FIFO、重复冷却、超时恢复和缺失回退有固定测试；
- 测试不调用真实模型、不读取 API Key，只使用 fake 驱动和本地数据。

## 真人目视清单

自动检查不能替代以下 main 项目：凯尔希透明背景与首帧、拖动条、右键缩放、设置滑条回写、展开/收起无瞬间放大、不同 Windows 缩放比例、长回复滚动，以及回复语气与最终动作是否自然一致。完成目视前只能标记“待人工验证”。

# V1.1a 可信长期记忆

V1.1a 为 For People No Friend 增加“先候选、后生效”的最小可信记忆闭环。它继续使用 Main Process 中的 SQLite 与关键词检索，不引入向量数据库、Embedding、Neo4j、Python 服务或新的画像 API Key。

## 用户能看到什么

- 用户明确说“记住：……”时，记忆仍会立即生效，不额外调用模型。
- 自动提取只进入“待你确认”，不会参与检索，也不会出现在聊天上下文里。
- 候选显示真实来源消息、日期、证据数量和不同日期数量；来源消息已清除时只保留日期与“原消息已清除”的说明。
- 冲突候选同时显示旧记忆。只有用户确认后才替换，拒绝不会改变旧记忆。
- 偏好、习惯、人物关系和时间不明确的未来事件会明确说明需要人工确认。模型不负责偷偷替用户拍板，它也没有这份编制。

## SQLite 迁移

Schema 版本从 1 升至 2，并新增：

- `memory_candidates`：候选正文、稳定键、状态、复核原因、冲突对象与决策时间；
- `memory_candidate_evidence`：候选关联的真实用户消息 ID 和消息日期。

迁移在单个事务中执行。旧版 `manual + active` 记忆保持有效；旧版 `automatic + active` 复制为带 `legacy_automatic` 标记的候选，原记录改为 `superseded` 并移出 FTS。迁移失败会整体回滚，成功后重复启动不会再次复制。

## 写入与确认规则

自动抽取结果必须带本批消息中的用户 `sourceMessageId`。Main 用当前完整用户消息构建允许列表；助手消息、编造 ID、越界结构和敏感内容均不能入库。

同一稳定键与正文再次出现时，候选会合并证据。候选始终不进入 `memories_fts`：

- 确认普通候选：创建已确认的 active 记忆；
- 确认冲突候选：先将旧 active 记忆标记为 superseded，再写入新版本；
- 拒绝候选：擦除正文和证据，只留下不可逆摘要指纹，避免同一内容反复打扰；
- 删除、忘掉和清空：同时擦除相关候选正文与证据。

确认后的自动候选保留 `source = automatic`，同时记录 `last_confirmed_at`，因此来源和人工决策不会混为一谈。用户之后手工编辑时，来源会转为 `manual`。

## 安全边界与降级

- Renderer 只调用候选列表、确认和拒绝三个固定 Preload 方法。
- Main 重新验证 IPC sender、候选 ID 和当前角色的 `memoryNamespace`，不能跨角色操作。
- 证据正文通过 SQLite 中真实消息关联读取，不采用模型回传的所谓“原文”。
- 候选、迁移或维护失败只跳过本轮记忆处理，不阻断文字聊天和本地角色显示。
- V1.1a 没有加入语音、Agent、MCP、工具调用、屏幕观察、桌面控制、打包或发布能力。

## 角色边界

本阶段不实现固定角色素材或 GIF 导入。现有 `memoryNamespace` 隔离保持不变，为后续带版本的泛用角色模板、每角色独立资源命名空间和必需的 `idle` 回退留出边界。

## 验证

自动测试覆盖 schema 迁移、旧自动记忆退出检索、人工记忆保留、候选证据合并、来源允许列表、冲突确认、拒绝擦除、时间软降级、命名空间隔离、IPC 输入与上下文注入。完整验证命令仍为：

```powershell
pnpm verify
```

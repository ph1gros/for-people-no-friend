# 语音资产按需下载

FPNF 的主程序不需要携带语音模型。未配置下载源或下载失败时，文字聊天、角色显示和
远程语音提供方仍然可用。

## 清单入口

应用默认读取资源仓库中的 speech-assets-v1.8.0.json；Main 环境变量
`FPNF_SPEECH_ASSET_MANIFEST_URL` 可显式覆盖或以空字符串停用，Renderer 不能提交或改写 URL。正式包只接受 HTTPS；本地开发运行可使用 `http://127.0.0.1`、
`http://localhost` 或 `http://[::1]` 做私密测试。

清单使用 schema 2，只提供档位 ID、版本和下载地址；不接受旧 schema、额外字段、
凭据、URL 片段、重复档位或重复下载地址。远程 `sha256`、`bytes`、`target` 字段一律拒绝。

```json
{
  "schemaVersion": 2,
  "tiers": [
    {
      "id": "voice-runtime",
      "version": "1.0.0",
      "urls": ["https://主源/voice-runtime.zip", "https://备源/voice-runtime.zip"]
    },
    {
      "id": "speech-input",
      "version": "1.0.0",
      "urls": ["https://主源/speech-input.zip", "https://备源/speech-input.zip"]
    }
  ]
}
```

当前采用独立组件布局，取代此前将 BERT 与音色并入第一档的方案：

- `voice-runtime`：Style-Bert-VITS2 引擎、Python 及运行依赖。
- `bert-japanese`：日语 DeBERTa ONNX 模型、配置和 tokenizer。
- `voice-ireina`：伊蕾娜 ONNX 音色、配置、风格数据及 `LICENSE.txt`。
- `speech-input`：SenseVoice 识别模型，目标目录仍为 `speech-input-runtime`。

前三项可以分别安装；实际启动下载版 TTS 必须同时验证三份编译期记录、激活标记及必需文件。
Main 向固定服务传入已验证的音色和 BERT 目录；Renderer 无法选择路径。旧的随包/开发布局仍兼容。
Genie 使用 `genie-tts`、`genie-data`、`voice-genie-mika` 三个独立档位，三者均须通过校验才启动。
本地引擎组件 1.0.1 已修正末尾占位值被合成为气声的问题；基础模型和音色仍为 1.0.0。
实际安装与合成已在回环下载源验证，七个组件已发布到 fpnf-resources，主程序已配置正式公开入口。

## 信任依据

`src/main/speech/speech-asset-integrity.ts` 中的编译期记录固定每档的版本、SHA256、
压缩大小、解压上限、文件数上限和安装目标。远程清单只能换源；版本不匹配或没有
内置记录的档位不可用。安装入口会再次从内置记录取得这些值，不信任调用方传来的副本。

七个生产记录均已用最终归档的实测数据填入并冻结。测试通过 Vitest 模块 mock 提供
临时假资产记录；生产代码没有从文件、环境变量、IPC 或网络覆盖哈希表的接口。

以后更新组件时，仍必须确认资产来源与分发许可，对最终 ZIP 实测 SHA256、压缩大小、解压
大小和条目数，将其作为冻结记录写入源码并重新分发应用。应用本身及构建分发渠道必须
可信；此设计只约束下载源的权限，不代表可以防止本机攻击者改写已安装文件。

## 激活规则

- 大文件默认用四段 Range 并发下载，各段独立保留进度；暂停或进程退出后可续传。
- 网络失败时按清单顺序尝试备用源；下载体积、Content-Length（如存在）和 Content-Range
  必须与应用内置记录一致。
- 下载前检查目标盘可用空间，至少需要 `解压大小 × 1.3 + ZIP 大小 + 500 MiB`；
  空间不足或无法检查时停止，给出中文提示。
- 合并后先校验整个 ZIP 的 SHA256，再流式解压到随机 staging 目录。
- SHA256 不符时删除损坏包并结束本次操作，不继续轮询镜像重复下载同一坏内容。
- ZIP 路径、文件数、解压体积、符号链接和目标目录全部校验通过后，才原子替换当前目录
  并写入 schema 2 激活记录。重启后的状态恢复及下载版 Python 启动都必须将该记录与
  内置版本/哈希比较，旧版无 schema 标记不能启用；仍会重新检查实际必需文件。
- 资源中心版本启动时只清理下载残留，第一档由用户点击安装后才下载。
  ASR 档在用户第一次点击麦克风时开始或继续。旧的 `scheduleInitialDownload` 方法保留兼容测试，
  当前 Main 不再调用它；其计费网络保护仍保持有效。
- 用户手动开始/继续时刷新网络状态（并发请求合并一次检测），计费或未知状态不会阻止主动下载，
  设置页与下载细条显示流量提示。Windows 检测隐藏窗口、超时 5 秒、输出上限 64 KiB；
  检测失败不当作非计费。此处未实现下载期间持续监测网络变化，相关真实切网验收仍待完成。

选择第二轮 R3 的路线 A：保留分段并发，完整下载并校验后再解压。它保留续传能力，
并避免在 SHA256 通过之前解压。峰值占用包括 ZIP、分片合并、staging 与更新时保留的
旧目录；当前内置表未启用。正式大包验收仍需实测峰值与预留量，不能以小型测试替代。

## 发布边界

公开展示目录已托管到 `ph1gros/fpnf-resources`，生产下载清单与最终组件 ZIP 尚未发布。
用户已于本轮确认伊蕾娜仅限非商业使用；现有 `resources/PRIVATE_ASSET_NOTICE.zh-CN.txt`
也载明保留说明后的非商业复制、分享及再分发条件。此限制只适用于相应角色/音色资产，
不覆盖语音引擎及基础模型原有许可。伊蕾娜独立包须携带相应 `LICENSE.txt`。
当前七个最终归档已有实测可信记录和 HTTPS 清单；后续更换归档仍需同步更新主程序。
仅设置清单环境变量不会启用未配置的档位。

## 崩溃残留的回收

`activate()` 在失败时会自行清理 staging 与 backup 目录，但进程被强制结束时那条路径不会执行，
而且每次尝试都用新的 UUID，所以残留不会被覆盖，只会累积——一个被遗弃的 staging 树可能占据
整个解压后的体积。

应用启动时（`initialize`，不依赖下载源）会扫描资产根目录，
只处理下载器生成的固定档位/目标加 UUID 目录名，不跟随符号链接，也不删除相似前缀的其他目录。
**未配置下载源时同样执行**。清理与手动安装共用一次性启动屏障，安装必须等待清理结束，
随后不会重复清理正在解压的目录。

staging 残留可回收；backup 只有在替换目录必需文件完整、当前激活记录匹配内置版本和哈希时才回收。
若进程在两次 rename 之间退出，backup 可能是仅存的旧副本，因此保留；不会据此自动恢复或启动它。
生产记录为 null 时也保留备份，可能仍占用磁盘，不能承诺清除一切崩溃残留。
`.downloads` 下的分段进度文件刻意保留，以免已传输部分在恢复时从零重来。

## 清单读取失败不缓存

开机自启的桌宠常常在网络就绪之前启动。清单请求失败时不会缓存失败结果，
下一次读取状态会重新尝试，用户不必重启应用。成功后清除清单加载的旧错误提示；
并发读取共用当前请求，旧失败请求不能清空一个更新的请求缓存。

## 公开下载的网络边界

清单 8 秒超时、256 KiB 流式上限，目录 8 秒超时、128 KiB 流式上限；无 Content-Length 时也限制读取。单次资产下载最长 30 分钟，失败保留可续传分片。GitHub Release 附件只允许从本资源仓库地址跳转一次到 HTTPS release-assets.githubusercontent.com。Electron 用 net.request 暴露重定向响应，不携带会话凭据；通过校验后以禁止后续跳转的请求取回文件。

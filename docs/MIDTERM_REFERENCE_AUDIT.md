## 记忆采用原则

两条路线共享完整的短期与长期记忆能力，差异只在默认上下文预算和表现方式：

- GIF Version：同样拥有最近完整轮次、摘要、当前场景、核心事实、事件回忆、候选画像、日记和混合召回；为本地小模型默认选择更少、更短的注入片段。
- Live2D Version：使用同一记忆治理与索引能力，可以为较强模型提供更丰富的关系、情绪和情景回忆；较大上下文也必须有预算。
- SQLite 继续保存可读正文、证据、确认状态和版本，是唯一不可替代的数据副本。
- Embedding、Qdrant 和 Neo4j 都是可关闭、可删除、可重建的辅助索引。索引损坏、服务未启动或召回失败时必须退回 SQLite 关键词路径。
- 向量召回不能跨人格，关系图不能把用户事实、角色世界观和作品社区词库混成一张图。
- 任一参考项目在某项记忆能力上表现更好时，以固定评测比较准确率、可解释性、延迟和失败回退，再把胜出的思路用于两条路线。

## 桌面交互边界

- “键盘捕捉”实现为用户选择并明确显示的全局快捷键和统计型活动事件；不保存字母、数字、密码、聊天正文或应用输入内容。
- 音乐控制只允许播放/暂停、上一首、下一首和读取用户允许显示的当前媒体信息；不获得任意进程、文件或桌面控制能力。
- 扩展接口采用声明式能力与权限清单。V1.5 首批只允许内部签名适配器，不加载第三方任意 JavaScript、命令或 DLL。
- 每项能力均可关闭，关闭后注销快捷键、停止事件订阅并清除非必要临时状态。

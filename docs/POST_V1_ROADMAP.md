# For People No Friend 1.0 之后路线

## 当前基线

M0～M5.2 组成 For People No Friend 1.0.0 功能基线。本仓库固定为 Live2D 完整功能主线。

伊雷娜动态 WebP 已迁至独立的 [GIF Version 仓库](https://github.com/ph1gros/for-people-no-friend-gif)。WebP Version 侧重本地小模型和快速角色扮演，同时也会记住重要的事情。两个版本都支持生成角色。

本路线图从此只记录 Live2D 主仓库的实现与规划，不再维护独立仓库的角色、素材格式、表现调度、语音回退或发布计划。角色生成继续遵循安全流程：只把用户确认的角色名和作品名发送给公开资料源，生成带来源的本地草稿，用户保存后才生效。

Live2D 主仓库沿着长期陪伴方向发展：稳定角色、可信长期记忆、连续但有边界的情绪、可解释的 Live2D 表现，以及安全的本地/远端模型协作。角色资料、用户记忆、近期对话、本轮情绪和 Live2D 调度保持独立边界。

未经用户明确授权，本路线不包含提交、推送、安装包、签名、自动升级、公开 Release 或真实密钥测试。

## 已完成：V1.1 可信记忆与泛用角色资料

- 自动提取先进入候选池，保留来源消息与日期；用户可以确认、拒绝、修改、合并或替换冲突记忆。
- 偏好、习惯、关系和未来计划不会根据一次普通对话静默成为正式记忆；事件和计划支持有效期。
- 角色资料支持身份、背景、关系、称呼、说话方式、情境示例和字段级来源。
- Main Process 校验角色命名空间与所有写入，Renderer 不直接接触 SQLite 或完整密钥。

## 已完成：V1.2 角色扮演资料库与体验基础

- 建立可追溯的角色扮演资料库，分别保存身份、经历、关系、场景、情绪、台词与说话方式。
- 引入固定角色问题、检索基线和跨轮连续性评估；作品词库具有独立命名空间、本地缓存和来源展示。
- 完成 Embedding、Qdrant 与 Neo4j 的采用门槛设计；SQLite 可读正文和关键词检索始终是基础回退。
- 完成长时间有界写入、重启读取、事务回滚、损坏回退、窗口恢复、设置持久化和 IPC 边界测试。
- 角色生成形成“公开资料查询 → 带来源草稿 → 用户确认保存”的闭环。

## 已完成：V1.3 Live2D 表现与短期连续性

- 建立 Motion、Expression、参数、视线、待机和一次性动作调度，并定义优先级、冷却、超时、恢复和缺失回退。
- 最近完整轮次、短摘要、当前场景和重要事实共同维持短期连续性；人格切换后按命名空间隔离。
- 使用最近已完成记录维持短期情绪连续性；临时心情不会写入长期记忆或关系等级。
- 增加 Live2D 能力报告、提示组成检查、生成生命周期保护和 Unicode 字符簇流式显示。
- 核对窗口尺寸、拖动、缩放、展开/收起、透明背景和表现故障回退；表现异常不得阻断文字聊天。

## 当前：V1.4 角色包、混合记忆与模型协作

当前实现状态：角色包往返、角色库与命名空间切换、上下文情境示例和冷却、上下文调试视图、经用户授权的模型协作、本机混合召回，以及可选 Qdrant / Neo4j 连接已经落地。外部索引和远端任务默认关闭；SQLite 正文、关键词回退和当前聊天模型始终保留。

- 角色包包含角色资料、字段级来源、情境示例、Live2D 清单、素材署名和兼容版本；私人聊天、用户记忆和真实模型密钥绝不导出。
- 导入前检查路径穿越、压缩包体积、重复命名空间、远程资源、清单版本、哈希和许可证说明，用户确认后才写入。
- 角色库在本仓库内切换资料、历史、摘要、长期记忆、作品词库、当前场景和 Live2D 表现资源。
- 角色调试视图显示本轮命中的角色资料、作品词条、情境示例、记忆、情绪与动作，以及预算和回退原因。
- 模型能力描述层记录流式、结构化输出、上下文长度、取消与超时特性。
- 普通聊天继续使用当前模型；复杂资料整理、角色卡补全和冲突判断只有在用户开启后才可交给指定远端模型，失败时回退当前模型。
- 本机混合召回融合关键词、向量、关系、重要度、时间和证据状态；外部索引不保存唯一正文，连接失败直接回退。
- 外部角色卡格式通过独立适配器转换为本项目 schema，不导入扩展脚本、工具定义或未知可执行内容。
- 发布前继续完成人工角色创建、角色包导入导出、Live2D 显示、快捷操作、媒体控制和第三方服务兼容性复测。

## 未来 V1.5：桌面功能与受限扩展

- 完善可配置快捷键、展开/收起、停止生成、临时静音和明确动作触发；只接收已注册组合键，不记录普通输入。
- 可选活动映射只产生“活跃、连续输入、空闲”等粗粒度状态，默认关闭，不保存原始按键或鼠标轨迹。
- 完善 Windows 媒体会话适配器，提供曲目信息、播放/暂停、上一首和下一首；失败不影响聊天。
- 角色可以根据已授权的媒体状态和应用内部事件做有限主动反应，并提供免打扰、频率限制和一键关闭。
- 建立声明式扩展接口，覆盖模型提供商、角色资料源、表现映射、媒体控制和快捷键动作；每项声明权限、数据去向、超时和回退。
- 视觉、屏幕观察、文件操作、命令执行和桌面控制不共享扩展授权，继续等待独立的高风险里程碑。

## 未来 V1.6：声音与实时对话

- 接入可取消、可失败回退的 ASR、TTS、VAD、音频播放和 Live2D 参数化口型。
- 支持按住说话、手动开始/停止和可选 VAD；常开麦克风不是默认值，必须显示明确收音状态。
- 本地与用户配置的兼容接口都要展示模型能力、语言、声音来源和数据去向，不读取未经授权的设备或密钥。
- 使用流式分句、音频队列、字幕同步和可中断播放；用户重新说话或点击取消时立即停止后续音频。
- 声音角色包记录音色 ID、推荐参数、语言和授权，不默认打包来源不明的声音模型。
- 语音失败时完整回到文字聊天，不能阻断记忆、角色资料或 Live2D 显示。

## 未来 V2：自然语音质量

- 优化 TTS、ASR、VAD、语音打断、字幕和口型同步的时延与稳定性。
- 通过既有 `SpeechInput`、`SpeechOutput` 与表现通道接入，不破坏文字对话。
- 麦克风权限、云端音频发送和声音模型来源必须清楚展示并可关闭。

## 未来 V3：用户长期记忆的高级基础设施

只有 SQLite 关键词检索在真实用户记忆中出现明确瓶颈时，才按以下顺序评估：

1. **Embedding**：可选语义召回；保留关键词回退、来源证据和用户删除能力。
2. **Qdrant**：只有规模和性能证明 SQLite 不足时才引入，不得成为基础聊天的强制依赖。
3. **Neo4j**：只有多人物、多事件、多跳关系成为明确需求时才评估，并先验证 SQLite 关系表是否足够。
4. **Python 记忆服务**：只作为可选高级模式，不要求普通用户配置 Python、Docker、固定端口或多个后台进程。
5. **独立画像模型**：允许用户明确选择独立模型，但默认复用现有安全模型路由；密钥仍由 Main Process 和 `safeStorage` 管理。

高级记忆不得把角色世界观、作品词库、用户画像和用户长期事实混成同一命名空间。任何自动提取结果都必须经过候选、证据、冲突和删除规则。

## 未来 V4：受控 Agent 与扩展能力

- Agent、MCP 和工具调用只在独立里程碑加入，不作为普通聊天的默认能力。
- 每个工具声明权限、输入范围、数据去向、失败行为和是否需要逐次确认。
- 高风险操作由 Main Process 重新校验，并提供可见确认、超时、取消和审计记录。
- 屏幕观察、桌面控制、代码执行和文件写入不能因接入 MCP 或 Agent 自动获得授权。
- 插件或工具故障不得阻断基础桌宠、文字对话和本地记忆管理。

## 未来：更长期的可选技术

- 评估本地 WebGPU 推理、浏览器数据库与多端架构；只有固定测试证明优于当前 Electron + SQLite 路线时才采用。
- VRM、MMD、Spine、立绘等新渲染器需要单独授权、素材许可和验收，不能挤进 Live2D 主线。
- 视觉理解、屏幕观察和桌面控制拆成不同权限；只读视觉不会自动获得鼠标键盘、文件或命令执行能力。
- 插件平台需要可信来源、权限清单、逐项启用、数据去向和审计，不能直接加载第三方任意脚本。
- Discord、Telegram、游戏协作和移动端属于独立产品集成，只有用户明确需要时才进入里程碑。

## 不变的开发规则

- 每个里程碑先审查用户指定项目的对应实现、许可证和官方依据，再设计和编码。
- MIT 项目如实际复用代码需保留许可声明；GPL 项目只学习设计和交互；没有明确许可证的代码不复制。
- 所有参考技术仍需通过本项目自己的单元、集成、构建和 Windows 目视验证。
- 测试使用 mock、fake、本地临时数据库和本地 HTTP，不索取、读取或使用真实 API Key。
- 未经用户明确授权，不提交、推送、制作安装包、发布产物或公开 Release。

# For People No Friend 1.0 之后路线

## 当前基线

M0～M5.2 组成 For People No Friend 1.0.0 功能基线。本仓库固定为 Live2D 完整功能主线；动态 WebP 已迁至独立的 [GIF Version 仓库](https://github.com/ph1gros/for-people-no-friend-gif)。两个项目共享文字陪伴、安全模型边界、本机 SQLite 长期记忆、结构化角色卡、侧拉对话 HUD、作品社区词库和角色草稿生成能力，但不在运行时跨表现层切换，也不互相列出对方的示例角色。

角色生成遵循同一条安全流程：只把用户确认的角色名、作品名发送给公开资料源，生成带来源的本地草稿，用户保存后才生效。共享的是资料结构和检索规则，不是表现资源：Live2D Version 只接收 Live2D 清单，WebP Version 只接收版本化 WebP 清单。以后即使各自支持多个自建角色，也只能在本版本内部管理，不能恢复凯尔希与伊蕾娜的跨版本切换。

## 两条产品路线

| 方向       | WebP Version                                     | Live2D Version                                              |
| ---------- | ------------------------------------------------ | ----------------------------------------------------------- |
| 首要目标   | 本地小模型也能快速做出一个可玩的角色             | 用能力更强的模型维持长期、细腻且可信的陪伴                  |
| 上手方式   | 紧凑角色卡、本地兼容接口、较小上下文、少量必填项 | 完整角色资料、来源证据、记忆管理与更细的模型配置            |
| 记忆定位   | 可用但不成为首次使用门槛，优先简单、透明、低开销 | 核心能力；强调候选确认、证据、冲突处理、时效与关系连续性    |
| 情感与表现 | 关键词驱动的清楚表情和动作，资源缺失就回到待机   | 情绪理解、回复语气、Live2D 表情与动作共同调度，并可解释回退 |
| 角色生成   | 快速生成紧凑资料；外观通过 WebP 素材清单接入     | 生成可追溯的丰富资料；外观通过 Live2D 素材清单接入          |
| 高级依赖   | 不把 Embedding、向量库或图数据库作为默认路线     | 只在评测证明有收益时提供可选索引；基础聊天始终可以安全回退  |

Live2D 沿着 `neuro-like` 的长期陪伴方向发展。这里具体参考的是 [my-neuro](https://github.com/morettt/my-neuro) 所强调的稳定角色、长期记忆、持续情绪和形象表现。角色资料、长期记忆、近期对话、本轮情绪和 Live2D 调度仍保持清楚边界；也不因为参考项目功能较多，就提前加入语音、Agent、工具调用或屏幕观察。

1.0.0 是代码与功能基线。V1.2 完成后，用户另行授权发布两个免安装 Windows 压缩包；当前仍不包含安装、签名、升级与卸载流程。

## V1.1a：可信长期记忆最小闭环

V1.1a 已完成最小可信闭环：自动提取先进入候选池，保留真实来源消息与日期；用户可以确认或拒绝；冲突、偏好、习惯、关系和不确定未来时间都不会静默生效；旧版自动活跃记忆会安全迁移为待确认候选。

- 自动提取结果先进入候选池，不立即注入对话。
- 记录来源证据、不同日期的复现次数和最近确认时间。
- 用户明确自述或手动确认可以晋升；普通习惯、偏好和关系需要重复证据。
- 一次性事件必须有时效，自动冲突先等待确认，不直接覆盖正式记忆。
- 设置页支持查看候选、证据、确认、拒绝、合并和软降级。
- 继续使用 SQLite 与关键词检索，不在本阶段引入外部记忆服务。

## V1.1b：候选整理与冲突决策

V1.1b 在不改变 V1.1a 数据库结构的前提下补齐人工整理入口：

- 候选确认前可以修改分类、正文、重要度、置信度和事件或计划的有效期。
- 相同稳定键的候选可以由用户明确合并；保留目标正文，合并来源证据并取较高的重要度与置信度。
- 冲突候选确认时可以选择替换旧记忆，或让新旧两条同时保留。
- 已确认的事件和计划也可以设置、修改或清除有效期；到期后仍按现有规则退出检索。
- 所有编辑、合并和确认继续由 Main Process 校验当前角色命名空间，Renderer 不直接接触 SQLite。

## V1.1c：泛用角色模板与伊雷娜

- 动态 WebP 模板和伊雷娜资源位于独立 GIF Version 仓库；Live2D 项目只吸收角色资料整理、情境对话、来源证据、共享设置同步等通用能力。
- 已定义可复用、带版本的动态 WebP 角色模板；新角色通过配置、媒体目录和资源清单创建，不需要重写聊天播放逻辑。
- 伊雷娜作为首个 WebP 角色包接入；现有角色与伊雷娜各自隔离角色卡、对话历史、摘要、长期记忆命名空间和表现资源。
- 角色联网整理在用户选择候选后继续发散查找身份、背景、关系和台词资料，生成称呼、说话方式与短台词示例，确认后才保存。
- 表现包使用统一的 `idle`、`thinking`、`talking`、情绪与动作通道；素材清单同时记录动作、情绪、道具、姿势、速度等多标签。
- `idle` 是必需的持续待机状态；其他资源缺失或加载失败时回退到 `neutral` 或 `idle`，不得阻断文字回复。
- 统一使用 `500 × 500` 逻辑显示画布，保留素材原始像素；新增素材在构建前检查 WebP 签名、动画、透明通道、尺寸、数量和清单引用。
- 伊雷娜资源包记录作者、原始页面和授权说明；来源 URL 只用于归属，不作为运行时远程资源加载。

## V1.1d：凯尔希 Live2D 公开示例

- `main` 为新安装提供凯尔希固定公开资料卡，包含身份、背景、关系、说话方式、情境表达参考与来源。
- 《明日方舟》作品社区词库继续使用独立命名空间和本地缓存；它不与角色资料或用户长期记忆混存。
- 已获得非盈利收录许可的“工作凯尔希”Live2D 运行素材与凯尔希资料卡共同作为完整示例；Cubism Core 仍由用户按官方条件自行放置。
- 不在这一阶段加入语音、Agent、MCP、屏幕观察或桌面控制。

## V1.2：角色扮演资料库与体验验证

- 已在 V1.1c 轻量角色卡之上建立可追溯的角色扮演资料库：身份、经历、关系、场景、情绪、台词与说话方式分别保存，并保留字段级来源。
- 为 WebP Version 定义本地小模型的紧凑提示预算和最少必填角色模板；资料生成后无需 Embedding 或额外资料服务即可开始角色扮演。
- 已为 Live2D Version 增加长期关系连续性和情绪回应评测：相同事实不反复遗忘、用户情绪不被粗暴贴标签、关心程度不无故跳变，回复情绪能稳定映射到现有表现通道。
- 已参考 SillyTavern 的角色卡分层和 RoleLLM 的“角色资料、情境知识、表达风格、角色验证”流程，补充固定问题、检索基线和跨轮连续性评估。
- 已完成 **Embedding** 可选接口与失败回退评测；当前关键词基线 5/5 命中，不安装模型或把语义索引变成基础依赖。
- 已完成**向量数据库**部署收益评估；当前 38 条资料不需要 Qdrant，未来只有规模与固定漏召回证明 SQLite 不足时才重评。
- 已完成 **Neo4j** 采用门槛设计；当前关系问题均为直接关系，没有证明图数据库收益的多跳用例。
- SQLite 继续保存用户确认过的正文、来源和版本；向量索引与关系图属于可重建的辅助索引，不能成为唯一数据副本。
- 角色资料、作品词库、用户长期记忆与表现资源保持独立命名空间、证据规则和删除生命周期，不因为采用相同检索技术而混在一起。
- 真人目视与真实 Electron 窗口实测按本阶段要求暂缓；现有纯逻辑测试继续覆盖 HUD 依赖的缩放、窗口恢复、表现调度和 IPC 边界。
- 已改善作品词库正文索引、来源展示、同步结果、失败明细和缓存校验。
- 已补充长时间有界写入、重启读取、事务回滚、损坏回退和本地数据一致性验证。
- Live2D 与独立 GIF Version 已对齐通用角色搜索、称谓生成、人格隔离和作品词库同步；两边继续保留各自的提示预算与表现资源。
- 共享设置已补自动验收：窗口缩放支持界面与运行时双向更新，提供商/模型、角色资料、记忆开关和作品词库状态支持持久化重载。
- 真人目视发烟不再作为 V1.2 尾项，统一进入 V1.3。

## M6：双版本角色生成收尾

- 两个版本都保留“公开资料查询 → 带来源草稿 → 用户确认保存”的角色生成能力。
- Live2D Version 使用较丰富的相关资料、可信长期记忆与本轮情绪边界；GIF Version 使用紧凑资料预算和现有的安全待机回退。
- 两边不暴露跨版本角色列举和激活入口，资料、记忆、作品词库与表现资源继续隔离。
- 自动测试、类型检查、构建和 Preload 安全检查是完成条件；真人目视发烟测试可以明确延后。
- M6 不恢复安装包规划，也不加入语音、Agent、MCP、屏幕观察或桌面控制。
- V1.2 功能完成后，用户另行授权发布两个免安装 Windows 压缩包；这不改变 M6 不设计安装、签名、升级与卸载流程的边界。

## V1.3：双路线角色表现与短期连续性

- `main` 重点吸收 AIRI、Soullink 与 Live2D 官方方案，建立可解释的 Motion、Expression、参数、视线、待机和一次性动作调度；目标是在 Live2D 长期陪伴体验上形成自己的优势。
- 独立 GIF Version 重点吸收 SillyTavern 与 RoleLLM，补齐 Character Card、当前场景、示例对话预算、World Info 激活和固定角色扮演评测；WebP 表现继续使用自己的标签与播放实现。
- 两条路线都补最近完整轮次、短摘要、当前场景和重要事实组成的短期记忆，并共同升级核心记忆、事件回忆、候选画像、日记和混合召回；人格切换后全部按命名空间隔离。
- 明确 Live2D 待机、思考、说话、情绪和一次性动作的优先级、冷却、超时、恢复与缺失回退。
- 使用最近四条已完成记录维持短期情绪连续性；新语义可以覆盖旧心情，短期情绪不写入长期记忆或关系等级。
- 保留 Motion、Expression、参数层、混合与连续动画的原生优势，不模仿 WebP 逐段播放。
- 核对窗口尺寸、拖动、右键缩放、设置滑条回写、展开/收起首帧和透明背景；自动检查与真人目视结果分开记录。
- 使用固定输入验证回复情绪、角色状态和最终表现一致，表现故障不得阻断文字聊天。
- 增加 Live2D 模型能力报告：核对 Motion Group、Expression Id、参数与资源引用，分别显示可用项、缺失项和实际回退，不再只给出笼统的加载失败。
- 引入轻量上下文注册表，将稳定角色核心、当前情境、短期情绪、长期记忆、作品资料和回复约束按来源组装；更新一层不得覆盖其他层。
- 补齐生成生命周期保护：同一人格内限制重复生成，取消、超时、迟到事件和人格切换后的旧事件不能污染新会话。
- 增加可展开的提示词组成检查，只展示资料类别、字符预算与来源，不泄露 API Key，也不把内部提示伪装成用户记忆。
- 采用 Character Note 思路保存当前场景中的短期条件；作品资料支持有界持续与冷却，仍以关键词、预算和人格命名空间为基础，不加入无限递归或自动脚本。
- 流式文字按 Unicode 字符簇提交到界面，避免中文标点、Emoji 和组合字符显示半截。
- 为 V1.4 的版本化角色包准备只读能力清单与 schema，不在 V1.3 自动导入未知压缩包。
- GIF 新素材先形成候选标签并由用户确认；待机、思考、说话、情绪和一次性动作具有明确优先级、时长、冷却和缺失回退。
- 两个仓库分别完成自动验证；共享改动通过明确的移植提交同步，不能用整分支覆盖破坏路线独立性。

## V1.4：角色包、混合记忆与模型协作

- 定义带版本的角色包：角色资料、字段级来源、情境示例、作品词库引用、Live2D 清单、素材署名和兼容版本放在同一包内；私人聊天、用户记忆和真实模型密钥默认绝不导出。
- 提供角色包创建、预览、导入、导出、升级与回滚。导入前检查路径穿越、超大压缩包、重复命名空间、远程资源、清单版本和许可证说明，用户确认后才写入。
- 建立本版本内部的角色库。切换角色时资料、历史、摘要、长期记忆、作品词库、当前场景与表现资源一起切换命名空间，不恢复 Live2D/WebP 跨路线切换。
- 增加角色调试视图：显示本轮命中的角色资料、作品词条、情境示例、记忆、情绪与动作，以及各层使用的预算和回退原因。
- 建立模型能力描述层，记录流式、结构化输出、上下文长度、取消与超时特性；不再把所有“兼容接口”假设成完全相同。
- 支持安全的本地/远端任务分工：本地模型可承担普通聊天，较复杂的资料整理、角色卡补全和冲突判断可以交给用户已经配置的远端提供商；不要求额外画像 API Key。
- 两条路线都采用核心记忆、可信长期事实、事件记忆、候选画像、按日摘要和可解释短期记忆报告；GIF 默认紧凑注入，Live2D 默认允许更丰富的关系与情境片段，但功能和数据治理同级。
- 首批实现本地 Embedding 适配器和固定语义改写评测；只有评测优于关键词基线才允许用户启用，模型缺失时不自动下载大文件。
- 比较 SQLite 内嵌向量索引与 Qdrant 可选适配器。Qdrant 不随应用强制启动，也不保存唯一正文；连接失败直接回退关键词检索。
- 实现 Neo4j 兼容的关系检索接口、内存假实现和固定多跳评测；只有多跳关系确实改善时才提供外部 Neo4j 开关。
- 混合召回按关键词、向量、关系、重要度、时间和证据状态融合；可选精排必须限制候选数量，并在界面说明为何命中。
- 路由失败、远端超时或可选索引不可用时回到基础文字聊天和关键词检索；路由选择与数据去向必须在界面中可见。
- Character Card V3 等外部格式先通过独立适配器转换为本项目 schema；保留原始来源和版本，不把外部扩展脚本、工具定义或未知可执行内容带入应用。
- 完成角色包往返、跨版本迁移、人格隔离、提供商能力假实现和路由失败回退的自动验收，再进行两个版本各自的真人角色创建流程测试。

## V1.5：桌面功能与受限扩展

当前已完成首批安全底座：固定组合键开关、窄 IPC、原子设置存储、媒体控制适配器接口和声明式扩展清单校验。全局快捷键默认关闭且不记录普通输入；Windows 媒体会话真实适配器、活动状态映射和主动事件仍待实现。

- 增加用户可配置的全局快捷键，用于展开/收起、停止生成、临时静音和触发明确动作；只接收已注册组合键事件，不记录普通键盘输入。
- 可选的键鼠活动映射只产生“活跃、连续输入、空闲”等粗粒度状态，用于桌宠动作；默认关闭，不保存原始按键或鼠标轨迹。
- 增加 Windows 媒体会话适配器，提供当前曲目信息、播放/暂停、上一首和下一首；每个控制动作由用户启用，失败不影响聊天。
- 角色可以根据已授权的媒体状态调整一句回复或表现，但模型不能直接指定任意播放器、文件路径或系统命令。
- 增加时间段、空闲状态、应用自身任务完成等内部事件，让角色拥有有限且可解释的主动反应；提供免打扰、频率限制和一键关闭。
- 建立声明式扩展接口，首批覆盖模型提供商、角色资料源、表现映射、媒体控制和快捷键动作。每个扩展声明权限、数据去向、超时和回退。
- 继续研究 AIRI 插件协议、EchoBot 三层隔离、BongoCat 输入映射和 ZcChat2 资产插件，但不加载任意第三方代码，不提前加入 MCP/Agent。
- 视觉、屏幕观察、文件操作、命令执行与桌面控制不共享“扩展”授权，继续等待更高风险的独立里程碑。

## V1.6：声音与实时对话

当前只完成可取消、可失败回退的 `SpeechInput`、识别器、`SpeechOutput` 与轮次协调接口，并使用 fake 自动测试。尚未请求麦克风权限，也未接入真实 ASR、TTS、VAD、音频播放或口型。

- 为 Live2D 与 GIF Version 提供同一套 `SpeechInput`、`SpeechOutput`、音频状态和取消接口；Live2D 使用参数化口型，GIF 使用 talking 动画回退。
- 支持按住说话、手动开始/停止和可选 VAD；常开麦克风不是默认值，必须显示清楚的收音状态。
- ASR 与 TTS 同时支持本地和用户配置的兼容接口，记录模型能力、语言、声音来源和数据去向，不读取未经授权的设备或密钥。
- 采用流式分句、音频队列、字幕同步和可中断播放；键盘停止、用户重新说话和取消按钮都能立即终止后续音频。
- 参考 Soullink 的连续情绪、AIRI 的音频流水线、EchoBot 的半双工防回声、ZcChat2 的流式语音和 my-neuro 的快速打断，独立实现并使用 fake microphone 自动测试。
- 声音角色包记录音色 ID、推荐参数、语言和授权；不默认打包来源不明的声音模型。
- 语音失败时完整回到文字聊天，不能阻断记忆、角色资料或模型显示。

## V2：自然语音

- TTS、ASR、VAD、语音打断和音频口型同步。
- 通过既有 `SpeechInput`、`SpeechOutput` 与表现通道接入，不破坏文字对话。
- 麦克风权限、云端音频发送和声音模型来源必须清楚展示并可关闭。

## V3：用户长期记忆的高级基础设施

V1.2 对角色资料检索的实验不会自动扩展到用户长期记忆。只有 SQLite 关键词检索在真实用户记忆中出现明确瓶颈时，才在独立命名空间按以下顺序评估：

1. **Embedding**：作为可选语义召回层；必须保留关键词回退、来源证据和用户删除能力。
2. **Qdrant**：只有记忆规模和向量检索性能证明 SQLite 不足时才引入；不得成为基础聊天的强制依赖。
3. **Neo4j**：只有多人物、多事件、多跳关系查询成为明确需求时才评估；优先确认 SQLite 关系表是否已经足够。
4. **Python 记忆服务**：只作为可选高级模式，不要求普通用户配置 Python、Docker、固定端口或多个后台进程。
5. **独立画像 API Key**：允许用户明确选择独立模型处理画像，但默认复用已选模型路由；密钥仍由 Main Process 和 `safeStorage` 管理，Renderer 不得读取完整值。

高级记忆不得把角色世界观、玩家社区词库、用户画像和用户长期事实混成同一命名空间。任何自动提取结果都必须经过候选、证据、冲突和删除规则。

## V4：受控 Agent 与扩展能力

- Agent、MCP 和工具调用只在独立里程碑中加入，不作为普通聊天的默认能力。
- 每个工具声明权限、输入范围、数据去向、失败行为和是否需要逐次确认。
- 高风险操作必须由 Main Process 校验，并提供可见确认、超时、取消和审计记录。
- 屏幕观察、桌面控制、代码执行和文件写入属于更高风险能力，不能因接入 MCP 或 Agent 自动获得授权。
- 插件或工具故障不得阻断基础桌宠、文字对话和本地记忆管理。

## 更长期的可选技术

- AIRI 的本地 WebGPU 推理、浏览器数据库与多端架构可作为性能和便携性评估对象；只有固定测试证明比当前 Electron + SQLite 路线更合适时才采用。
- VRM、MMD、Spine、立绘等新渲染器使用统一角色表现语义和角色包边界，但每条渲染路线都需要单独授权、素材许可和验收，不能挤进 Live2D 主线。
- 视觉理解、屏幕观察和桌面控制必须拆成不同权限。未来即使加入只读视觉，也不会自动获得鼠标键盘、文件或命令执行能力。
- 插件平台需要签名或可信来源、权限清单、逐项启用、数据去向和审计；不能直接加载第三方任意脚本。
- Discord、Telegram、游戏协作和移动端属于独立产品集成，只有用户明确需要时才进入里程碑。

## 不变的开发规则

- 每个里程碑先审查用户指定项目的最新实现、许可证和官方依据，再设计和编码。
- 不复制 GPL 或未授权源码；参考项目只用于理解架构、交互、故障恢复和测试方法。
- 测试使用 mock、fake、本地临时数据库和本地 HTTP，不索取或使用真实 API Key。
- 未经用户明确授权，不制作安装包、发布产物或公开 Release。

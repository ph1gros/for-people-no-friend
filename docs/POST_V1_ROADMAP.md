# For People No Friend 1.0 之后路线

## 当前基线

M0～M5.2 组成 For People No Friend 1.0.0 功能基线。当前版本固定以下核心方向：Windows、Live2D、文字陪伴、安全的模型提供商边界、本机 SQLite 长期记忆、结构化角色卡、侧拉对话 HUD 和用户主动同步的作品社区词库。

1.0.0 是代码与功能基线。当前路线不包含 Windows 安装包、签名、升级、卸载或可执行发布产物。

## V1.1a：可信长期记忆最小闭环

V1.1a 已完成最小可信闭环：自动提取先进入候选池，保留真实来源消息与日期；用户可以确认或拒绝；冲突、偏好、习惯、关系和不确定未来时间都不会静默生效；旧版自动活跃记忆会安全迁移为待确认候选。

- 自动提取结果先进入候选池，不立即注入对话。
- 记录来源证据、不同日期的复现次数和最近确认时间。
- 用户明确自述或手动确认可以晋升；普通习惯、偏好和关系需要重复证据。
- 一次性事件必须有时效，自动冲突先等待确认，不直接覆盖正式记忆。
- 设置页支持查看候选、证据、确认、拒绝、合并和软降级。
- 继续使用 SQLite 与关键词检索，不在本阶段引入外部记忆服务。

## V1.1b：候选整理与冲突决策

V1.1b 在不改变 V1.1a 数据库结构的前提下补齐人工整理入口：

- 候选确认前可以修改分类、正文、重要度、置信度和事件或计划的有效期。
- 相同稳定键的候选可以由用户明确合并；保留目标正文，合并来源证据并取较高的重要度与置信度。
- 冲突候选确认时可以选择替换旧记忆，或让新旧两条同时保留。
- 已确认的事件和计划也可以设置、修改或清除有效期；到期后仍按现有规则退出检索。
- 所有编辑、合并和确认继续由 Main Process 校验当前角色命名空间，Renderer 不直接接触 SQLite。

## V1.1c：泛用角色模板与伊雷娜

- Live2D 保持 `main` 主线；动态 WebP 使用独立 `gif-version` 支线。两边共享聊天、记忆和角色资料能力，但不在运行时提供跨表现层切换。
- 已定义可复用、带版本的动态 WebP 角色模板；新角色通过配置、媒体目录和资源清单创建，不需要重写聊天播放逻辑。
- 伊雷娜作为首个 WebP 角色包接入；现有角色与伊雷娜各自隔离角色卡、对话历史、摘要、长期记忆命名空间和表现资源。
- 角色联网整理在用户选择候选后继续发散查找身份、背景、关系和台词资料，生成称呼、说话方式与短台词示例，确认后才保存。
- 表现包使用统一的 `idle`、`thinking`、`talking`、情绪与动作通道；素材清单同时记录动作、情绪、道具、姿势、速度等多标签。
- `idle` 是必需的持续待机状态；其他资源缺失或加载失败时回退到 `neutral` 或 `idle`，不得阻断文字回复。
- 统一使用 `500 × 500` 逻辑显示画布，保留素材原始像素；新增素材在构建前检查 WebP 签名、动画、透明通道、尺寸、数量和清单引用。
- 伊雷娜资源包记录作者、原始页面和授权说明；来源 URL 只用于归属，不作为运行时远程资源加载。

## V1.1 后续：M3 固定角色

- 为 M3（Mon3tr）补充固定角色资料和版本化表现包，复用 V1.1c 的模板、标签与隔离机制。
- 不在这一阶段加入语音、Agent、MCP、屏幕观察或桌面控制。

## V1.2：角色扮演资料库与体验验证

- 在 V1.1c 轻量角色卡之上建立可追溯的角色扮演资料库：身份、经历、关系、场景、情绪、台词与说话方式分别保存，并保留字段级来源。
- 重新设计动态 WebP 表现策略：入场、思考、说话、短暂情绪、一次性动作、持续状态和随机待机采用明确的优先级与恢复时间，不再让回复情绪长期压住思考或说话状态。
- 参考 SillyTavern 的角色卡分层和 RoleLLM 的“角色资料、情境知识、表达风格、角色验证”流程，补充固定测试问题与多轮角色一致性评估。
- **Embedding** 参与角色台词、经历和情境示例的语义召回；仍保留关键词召回，并只向单次对话注入少量相关片段。
- **向量数据库**作为可选资料索引层评估。先验证规模、效果和部署成本，再决定使用 SQLite 内嵌方案或 Qdrant；索引损坏或服务未启动时回退到 SQLite 关键词，不阻断普通聊天。
- **Neo4j** 参与人物关系、事件先后和跨条目关联的实验设计；只有多跳关系确实提高角色回答质量时才接入，简单关系继续使用 SQLite。
- SQLite 继续保存用户确认过的正文、来源和版本；向量索引与关系图属于可重建的辅助索引，不能成为唯一数据副本。
- 角色资料、作品词库、用户长期记忆与表现资源保持独立命名空间、证据规则和删除生命周期，不因为采用相同检索技术而混在一起。
- 增加真实 Electron UI 自动化，覆盖 HUD、长回复、角色身份、拖动、缩放和窗口恢复。
- 改善作品词库正文索引、来源展示、同步进度、失败明细和缓存管理。
- 补充长时间运行、错误恢复和本地数据一致性验证。

## V2：自然语音

- TTS、ASR、VAD、语音打断和音频口型同步。
- 通过既有 `SpeechInput`、`SpeechOutput` 与表现通道接入，不破坏文字对话。
- 麦克风权限、云端音频发送和声音模型来源必须清楚展示并可关闭。

## V3：用户长期记忆的高级基础设施

V1.2 对角色资料检索的实验不会自动扩展到用户长期记忆。只有 SQLite 关键词检索在真实用户记忆中出现明确瓶颈时，才在独立命名空间按以下顺序评估：

1. **Embedding**：作为可选语义召回层；必须保留关键词回退、来源证据和用户删除能力。
2. **Qdrant**：只有记忆规模和向量检索性能证明 SQLite 不足时才引入；不得成为基础聊天的强制依赖。
3. **Neo4j**：只有多人物、多事件、多跳关系查询成为明确需求时才评估；优先确认 SQLite 关系表是否已经足够。
4. **Python 记忆服务**：只作为可选高级模式，不要求普通用户配置 Python、Docker、固定端口或多个后台进程。
5. **独立画像 API Key**：允许用户明确选择独立模型处理画像，但默认复用已选模型路由；密钥仍由 Main Process 和 `safeStorage` 管理，Renderer 不得读取完整值。

高级记忆不得把角色世界观、玩家社区词库、用户画像和用户长期事实混成同一命名空间。任何自动提取结果都必须经过候选、证据、冲突和删除规则。

## V4：受控 Agent 与扩展能力

- Agent、MCP 和工具调用只在独立里程碑中加入，不作为普通聊天的默认能力。
- 每个工具声明权限、输入范围、数据去向、失败行为和是否需要逐次确认。
- 高风险操作必须由 Main Process 校验，并提供可见确认、超时、取消和审计记录。
- 屏幕观察、桌面控制、代码执行和文件写入属于更高风险能力，不能因接入 MCP 或 Agent 自动获得授权。
- 插件或工具故障不得阻断基础桌宠、文字对话和本地记忆管理。

## 不变的开发规则

- 每个里程碑先审查用户指定项目的最新实现、许可证和官方依据，再设计和编码。
- 不复制 GPL 或未授权源码；参考项目只用于理解架构、交互、故障恢复和测试方法。
- 测试使用 mock、fake、本地临时数据库和本地 HTTP，不索取或使用真实 API Key。
- 未经用户明确授权，不制作安装包、发布产物或公开 Release。

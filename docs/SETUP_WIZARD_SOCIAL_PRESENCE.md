# 社交存在配置引导 / Social Presence Setup Guide

面向使用者的配置说明，对应社交存在功能（设计分期 PR 1–6）。它为**同一个角色**提供 QQ、KOOK 和实验性 Oopz 接入，按身份与会话场景隔离记忆。发布与验收状态以[交付记录](SOCIAL_PRESENCE_DELIVERY.md)为准。

**它不是首次运行向导的一步。** 首次运行向导（见[向导实现](SETUP_WIZARD_IMPLEMENTATION.md)）只覆盖服务商、角色与语音资源；社交存在是「设置 → 社交存在」页里的独立配置，三个平台默认全部关闭，不配置就完全不生效，也不影响桌面聊天。

## 前置条件

- 已完成首次运行向导，且**对话服务商与模型可用**。社交回复走的是和桌面聊天同一条生成链路，服务商没配好则任何平台都不会回话。
- 已选定当前角色。所有社交配置**按角色隔离**，切换角色不会继承上一个角色的账号、凭据或主人绑定。
- 平台侧的机器人已在各自开放平台创建完毕。本应用不代为申请、注册或托管任何账号。

## 通用流程

三个平台的面板都在同一页，操作顺序一致：

1. 勾选「启用 ⋯ 社交存在」，填写账号标识与凭据。
2. 点「保存 ⋯ 设置」。**有未保存的修改时连接按钮会被禁用**，必须先保存。
3. 点「连接 ⋯ 」。状态行显示：尚未配置 / 已断开 / 连接中 / 已连接 / 连接失败。
4. 「刷新状态」按需手动拉取；页面隐藏时不轮询。

凭据只在主进程加密保存，**保存后不回显**：密码/密钥输入框留空表示「保留已存的」，不是「清空」。要真正删除请用面板底部的删除按钮。离开本页会丢弃未保存的草稿并清空凭据输入框。

切换角色、编辑角色资料、重跑设置向导都会**立即断开全部社交连接**，不会自动重连——这是有意的，避免旧角色的连接说着新角色的话。

## QQ

| 字段              | 说明                                            |
| ----------------- | ----------------------------------------------- |
| QQ App ID         | QQ 开放平台机器人的 App ID                      |
| QQ App Secret     | 加密保存，留空保留已存值                        |
| 主人 owner openid | 可选。**必须是当前机器人的 openid，不是 QQ 号** |
| 用语音回复        | 默认关闭                                        |

要点：

- 修改 App ID 会**重置该角色的全部主人绑定与已存 Secret**——QQ 的 openid 是按 App ID 派生的，换了 App 旧 openid 就不再指向同一个人。
- 「用语音回复」需要可选的 SILK 编码组件；组件不可用时能力不会被声明，回复自动退回文字。语音合成要求服务商输出 WAV，配成 MP3 会跳过语音、只发文字。
- 群聊里默认必须 @ 或引用角色才会回复；私聊默认直接回复。

## KOOK

| 字段              | 说明                     |
| ----------------- | ------------------------ |
| KOOK Bot Token    | 加密保存，留空保留已存值 |
| 主人 KOOK 用户 ID | 可选                     |
| 语音频道 ID       | **不会自动加入**         |
| 公开朗读文字      | 最多 1000 字             |

语音频道是**显式的三步操作**，没有任何自动加入或自动说话：「加入语音频道」→「公开朗读」→「停止并离房」。角色进房后会持续发送保活；连续两次保活失败会主动离房，而不是挂着一个看起来还在、其实已经掉线的成员身份。

朗读的是你在输入框里写的那段文字，**面向房间里所有人公开播放**，不是私聊内容。

## Oopz（实验性，当前无法启动）

Oopz 是社区逆向的非官方桥接，与前两者有本质区别：

- 它需要一个**独立的桥接子进程**，该进程运行时必须接触明文账号密码。
- 桥接进程与 OneBot 连接是**两条独立生命周期**：启动进程不会自动连接，连接也不会自动启动进程，必须分别操作。
- 进程状态显示「进程运行中」**只表示子进程已启动**，不代表已登录 Oopz，也不代表 OneBot 已就绪。目前没有认证的就绪握手。

**当前版本没有接入经过审核的桥接运行时，因此启动会被直接拒绝，已保存的密码也不会被解密。** 这是有意的 fail-closed 行为，面板会明确说明。想真正跑起来，还需要完成[尚未完成](#尚未完成)里的三项。

其他约束：OneBot 端点**只接受本机地址**（`127.0.0.1` / `::1` / `localhost`），端点里不允许带用户名密码；保存账号密码前必须勾选版本化的实验风险声明；账号与密码必须一起填写。建议使用专用测试账号——协议变化可能导致登录失败或账号受限。

## 主人绑定与记忆边界

这是整个功能里最需要理解的一节。角色在社交平台上遇到的每个人都会被归类为 owner / known-user / guest / unknown，**归类只来自你在面板里做的显式绑定，绝不采信消息正文里的自称**。

记忆按来源隔离，写入不同的命名空间：

| 场景        | 作用域   | 效果                                               |
| ----------- | -------- | -------------------------------------------------- |
| 主人私聊    | private  | **与桌面聊天共用同一份记忆**，跨平台延续同一段关系 |
| 他人私聊    | personal | 每人一个独立记忆池，只在与同一人再次私聊时可用     |
| 群聊 / 频道 | channel  | 按频道隔离，只在同一频道内可用                     |

召回同样受限：主人的私人记忆**永远不会在群聊里被使用**，哪怕说话的就是主人本人；一个人说过的话不会出现在另一个人的对话里。

因为主人私聊与桌面聊天共用同一份记忆，两边的回合会**串行**：你在社交平台上私聊角色的同时又在桌面窗口发消息，后到的那条会等前一条生成完，期间界面显示「正在等待上一轮对话结束…」。这是为了避免两条链路同时写同一份历史，不是卡死。其他作用域各自独立，不会互相排队。

群聊里角色使用的是**删减过的公开人设**——涉及主人称谓、私密关系、关系设定与对话范例的字段会被整体扣留，不会带进群聊提示词。

清除绑定：勾选「保存时清除全部主人绑定」再保存。每角色每平台最多 8 个主人账号。

## 什么时候会回话

按顺序过三道闸：

1. **硬门控**：自己发的消息、被封禁的人、被关闭的私聊一律不进模型；群聊默认必须 @ 或引用。未被呼叫的群聊消息只是「旁观」，不触发回复，也不会保存旁观者的正文。
2. **轮次调度**：每角色 / 平台 / 频道独立排队，@ 与引用优先。群聊回复后冷却 1 秒；等待超过 15 秒的旧消息直接丢弃。
3. **限流**：10 秒滑动窗口内，同一频道每人最多 4 轮、整个频道最多 12 轮。**主人也不豁免。**

全局同时处理最多 4 个对话、待处理最多 32 条；超出直接丢弃而不是排队堆积。生成与发送共享 60 秒取消期限。

## 出问题时

| 现象                 | 处理                                                                                                     |
| -------------------- | -------------------------------------------------------------------------------------------------------- |
| 状态一直「连接失败」 | 界面上的错误一律是脱敏后的固定文案（避免泄露凭据与服务商诊断）。请核对账号标识与凭据，必要时删除凭据重填 |
| 连接按钮点不动       | 有未保存的修改，或平台未启用，或凭据未保存。先保存                                                       |
| 角色不在群里回话     | 默认要求 @ 或引用；也可能撞上冷却或限流窗口                                                              |
| 语音发不出去         | 检查语音服务商是否输出 WAV；可选编码组件缺失时会静默退回文字                                             |
| Oopz 启动被拒        | 预期行为，当前没有接入经过审核的运行时                                                                   |

任何一个平台失败都**不会影响桌面文字聊天**。

未完成的运行时与真实账号验收统一记录在[交付记录的 maintainer 验收清单](SOCIAL_PRESENCE_DELIVERY.md#maintainer-人工验收清单)。请以该记录为准，不把本配置说明当作已通过端到端验收的证明。

## 为什么没并进首次运行向导

社交存在需要外部平台的机器人账号与密钥，拿到这些的前提是使用者已经在各平台完成申请——这不是首次启动时能顺手做完的事。把它放进向导会让绝大多数只想要一个桌宠的用户被迫跳过一整段步骤，也会让「默认全关」这个安全默认变得不明显。

如果以后要并进向导，按[扩展指南](SETUP_WIZARD_EXTENSION_GUIDE.md)加页，并保持三条不变量：默认关闭、凭据只走 `SecretStore`、跳过该页不影响任何既有功能。

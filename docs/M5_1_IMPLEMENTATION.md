# M5.1 联网角色卡实现

M5.1 在 M5 长期记忆之后增加结构化角色卡和由用户主动触发的公开资料查询。角色设定与用户长期记忆继续分开存储和注入。

## 已实现范围

- 设置页提供角色名称、来源作品或游戏，以及可展开的详细角色资料字段；
- 用户点击“联网查找”并确认隐私提示后才发送查询；
- 候选显示名称、作品、资料站点、摘要和匹配理由；
- 用户选择候选后才读取详情，并使用当前对话模型尝试整理结构化草稿；
- 模型未配置或整理失败时只保留名称、作品和资料来源，详细字段留空，不把网页原文误填为角色设定；
- 草稿不会自动保存，用户检查并点击总设置的“保存”后才落盘；
- 保存后的核心身份、性格和说话方式在每轮对话中使用，长背景与关系只在相关问题中加入；
- 支持取消搜索，关闭窗口时会终止仍在运行的查询。

## 当前资料源

- Arknights Terra Wiki；
- PRTS Wiki；
- 中文维基百科；
- English Wikipedia。

作品提示 `明日方舟` 或 `Arknights` 会选择两个明日方舟社区 Wiki，并在站内只搜索角色名，避免中英文作品名干扰站内搜索。候选先由响应更稳定的 Arknights Terra Wiki 确认；生成草稿时会同时尝试读取 PRTS 的 `<角色名>/语音记录`，让中文原作台词优先进入扮演设定。PRTS 暂时不可达时仍可使用 Arknights Terra Wiki 的 File 与 Dialogue，不会阻断生成。`凯尔希 + 明日方舟` 是本版本的固定验收样例。

资料源使用 MediaWiki Action API 的搜索、纯文本摘要和受限解析接口。解析后的 HTML 只在 Main 中转换成受长度限制的纯文本，不会进入 Renderer。

## 模型整理

详情读取完成后，`ModelRuntime` 复用当前选定的 Anthropic、OpenAI Compatible 或 Ollama 模型执行一次角色资料整理任务。整理目标以角色扮演为主：优先分析 Dialogue、语音记录和台词，总结对用户的称呼、语气、句式、惯用词、情绪表达、禁忌表达及少量短例句；身份和背景只保留影响角色认知与谈吐的事实。提示词明确把网页内容视为不可信参考资料，要求忽略网页内指令，只返回限定字段的 JSON，并在证据不足时留空。支持该能力的 Claude 模型使用 Anthropic 官方 JSON Schema 结构化输出，避免普通文本 JSON 被截断或格式错误；兼容提供商继续使用受校验的 JSON 提取路径。

保存后，说话方式会作为每轮对话都必须执行的扮演规则注入；模型被要求以角色本人而非资料解说员的方式回应，不向用户复述角色卡，也不机械照抄示例台词。

角色感必须贯穿观点、内容取舍、措辞和句子节奏，不能只在通用答案首尾添加角色称呼。日常回复默认保持二至五句；只有用户明确要求详细分析时才展开。面对原作外话题仍使用角色的认知方式，但不生硬堆砌原作术语。涉及新闻等实时信息而没有可验证资料时，不能把训练知识冒充为当前事实。

候选确认后的角色正式名称和来源作品由 Main 中的搜索记录锁定，整理模型无权覆盖；模型只生成别名、身份、性格、背景、关系和说话方式，避免把作品标题误写成角色名称。

联网查询不读取、记录或暴露 API Key。模型调用仍通过现有 `SecretStore` 与提供商适配器；自动测试只使用 fake fetch 和 fake generator。

## 安全边界

- 网络请求只在 Electron Main 中执行；
- Renderer 只能调用搜索、生成草稿、取消三个窄 IPC；
- 所有 IPC 都验证 sender、请求 ID、字符串长度和候选 ID；
- 候选 ID 是 Main 生成的短期随机句柄，Renderer 不能传任意 URL 请求页面；
- 当前资料源的 origin 和 API 路径固定，拒绝跨域响应与重定向；
- 资料请求有 5 秒超时，模型整理有 30 秒超时；响应有 Content-Type、Content-Length 和实际字符数限制；
- 原始 HTML 不使用 `innerHTML`，只输出纯文本数据；
- 名称与作品完全匹配时只返回最佳候选，否则最多显示 3 个候选；保存不超过 8 个来源，并限制提供给模型的总文本长度。

## 降级行为

- 单个资料源失败不会阻断其他来源；
- 所有来源失败时提示用户稍后重试或手动填写；
- 模型未配置、无 Key、超时或输出无效时保留名称、作品与资料来源，详细字段留空并提示重试或手动填写；
- 不支持模型原生网页搜索的 OpenAI Compatible/Ollama 不会被误标为支持；
- 任何角色查询失败都不影响普通聊天、历史与 M5 长期记忆。

## 尚未实现

设计文档中的提供商原生广泛网页搜索、自定义社区 Wiki 注册和单页 URL 导入仍是后续 M5.1 增量，不在当前可试运行切片中。界面与服务边界已经为这些来源保留扩展点，但不会声称已经搜索整个互联网。

完整设计见 [M5.1 联网角色卡设计](M5_1_DESIGN.md)，对话行为规则见 [M5.1 角色扮演约束](M5_1_ROLEPLAY_CONSTRAINTS.md)。

## 验证

自动验证覆盖 IPC 参数、来源相关性排序、HTML 摘要清理、详情草稿、无模型降级、取消操作、配置兼容、上下文注入和现有 M1～M5 回归。本地最终验证为 25 个测试文件、86 项测试全部通过，并通过 ESLint、Prettier、TypeScript、生产构建和 Electron Preload 安全冒烟。

公开接口实网冒烟确认 Arknights Terra Wiki 能把 `凯尔希 + 明日方舟` 收敛为对应角色候选，并能读取角色主页、档案和语音页。PRTS Action API 也通过系统网络单独确认能返回凯尔希页面；首选站点不可达时再查询后备来源，避免正常路径等待所有站点。

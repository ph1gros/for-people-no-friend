# M5.2 对话体验与新词理解修整

## 背景

M5.1 完成后，现有文字对话仍有三个直接影响日常使用的问题：回复气泡覆盖 Live2D 角色、HUD 过于厚重且不透明、界面仍用“桌宠”代替当前角色名称。此外，模型面对拼音缩写、社区黑话和近期热词时可能不知道、误猜或用过时含义回答。

因此取消当前 M6 发布尝试，先执行 M5.2。M6 仍是未来第一版发布阶段，但只有 M5.2 验收完成后才重新启动。

## 范围

### 对话 HUD

- 重做整个对话 HUD，而不是只移动现有字幕气泡。
- Live2D 显示区和聊天区必须分离；聊天正文不得盖住角色主体。
- 对话发生时，聊天区从角色侧面展开；收起后恢复为以角色为主的桌宠窗口。
- HUD 使用更轻的半透明背景，减少大面积深色遮罩和厚重阴影，同时保证文字可读。
- 输入框、流式回复、历史入口和操作按钮使用一致的布局与视觉语言。

### 长回复

- 当前回复必须完整保留，不生成界面摘要，不截断正文。
- 内容超过可视高度时在当前聊天区滚动，用户无需进入历史记录才能读完。
- 流式生成期间保持稳定布局，不因文本增长反复遮挡角色或改变 Live2D 缩放。
- 停止生成、错误和重试状态不能覆盖已经收到的正文。

### 当前角色身份

- 输入框提示使用当前角色卡名称，例如“和凯尔希说点什么……”。
- 回复署名、历史记录署名和相关状态使用同一个当前角色名称来源。
- 修改并保存角色卡后立即刷新 HUD，不要求重启。
- 角色卡名称优先于 Live2D 模型名称；两者都没有时才显示“桌宠”。

### 缩写、黑话与新词

- 优先使用当前对话上下文、角色语境和已知本地词义判断含义。
- 同一个缩写存在多个合理解释时，明确说明不确定并询问用户所指语境。
- 不允许为了保持角色口吻而虚构词义或假装了解新词。
- 用户纠正后可以将词义保存在本地个人词表；不得混入角色世界观事实或长期偏好。
- 联网查词只能由用户明确触发，每次展示查询状态和来源；普通聊天不能静默联网。
- 联网失败时回退为澄清问题，不影响正常对话。

### 作品域社区词库

- 角色卡的 `sourceWork` 决定优先词库；当前内置首个经过人工核对的“明日方舟”词库。
- 每条记录包含 `term`、`aliases`、`meaning`、`originContext`、`sources`、`lastVerified` 和 `confidence`。
- 发送模型前只对当前消息做精确词条/别名匹配，最多注入三条相关内容，并明确标记为玩家社区语境而非角色世界观事实。
- 内置校对快照可以离线命中；用户可在设置中明确触发“同步作品词库”，同步时才访问公开来源并把交叉验证结果缓存到本地。
- 明日方舟同步会通过粥批手册的 MediaWiki API 遍历正文页，读取页面标题、重定向别名、修订时间和原始链接；不会依赖搜索引擎摘要。同步后的普通聊天只查询本地索引。
- 单一来源只能形成低置信度结果；来源无法互相印证时保留原缓存并要求澄清，禁止把搜索摘要直接写成事实。
- “325”词条区分游戏内结算 325 分与包含额外加分的赛事总分 395，来源包括粥批手册低分梗页、萌娘百科仙术杯页与 Bilibili 社区梗资料。

## 验收条件

1. 使用长回复连续对话时，正文完整可读且不覆盖 Live2D 角色主体。
2. HUD 相比当前实现明显更透明，文字仍具备足够对比度。
3. 保存新角色名称后，输入提示和所有回复署名立即更新，不再固定显示“桌宠”。
4. 对 `xnn` 这类含义依赖社区和上下文的缩写，系统不会无依据给出唯一答案；能先澄清，或在用户明确触发后联网查证并标注来源。
5. 窗口拖动、65%～150% 缩放、窗口中心缩放、多显示器可见区域恢复和 Live2D 四通道控制不回归。
6. 全部测试、类型检查、生产构建和 Electron Preload smoke 通过。

## 非目标

- 不生成 Windows 安装包，不进行签名、升级、卸载或干净系统发布验收。
- 不实现普通聊天的自动全网搜索。
- 不实现 TTS、ASR、VAD、语音打断或口型音频同步。
- 不加入 MCP、Agent、插件市场、屏幕观察、桌面控制或任意工具调用。
- 不改动 M5.1 已确定的角色扮演约束和角色/作品锁定规则。

# V1.6 声音与实时对话实施基线

## 本轮范围

V1.6 先建立不会破坏文字聊天的音频输出主干：模型流式文本经过独立分句器，完整第一句出现后就开始日语转换和 TTS，不再等待整段文字回复结束；最多并行准备两个短音频片段，但始终按原文本顺序播放。过短的开头会和下一句合并，避免把“嗯？”等语气词单独切碎。音色模型、采样率、语速和翻译约束不因低延迟模式降低。每轮语音拥有独立请求 ID 和取消信号；用户点击“停声”、停止生成、开始新一轮、关闭语音或退出窗口时，会同时取消待生成片段、当前播放与 Live2D 口型。

首个提供商是 Main Process 中的 OpenAI 兼容 `/audio/speech` 适配器。它既可连接本机兼容服务，也可连接用户明确配置的远端服务；本机只允许 `localhost`、`127.0.0.1` 或 `::1` 的 HTTP，其他地址必须使用 HTTPS。请求限时，拒绝重定向，响应只接受有限音频 MIME，最大 16 MiB。API Key 单独保存在 `safeStorage` 加密的密钥库中，Renderer 只能看到“是否已保存”。

语音输出默认关闭，伊蕾娜 TTS 的默认语速为 `0.90`；句内边界保留约 `90` 毫秒停顿，跨生成片段的句尾保留约 `280` 毫秒停顿。界面会显示提供商、模型、音色、语言、音频格式、声音来源和数据去向。TTS 失败只停止本轮声音，已经显示的文字、记忆、角色资料和 Live2D 仍可继续使用。

中文麦克风输入同样默认关闭，并提供“完全、精准、手动”三种互斥模式。完全模式识别到一句完整的话就自动发送；若上一句仍在回复或朗读，且用户在上一句说完后的 2 秒内继续开口，两段输入会合并并重新思考；超过 2 秒的输入会进入最多 4 句的有界等待队列。精准模式只接受同一句开头的“小猫 + 内容”；两者在 Renderer 本地用有上限的 VAD 切分语音，再通过窄 IPC 交给 Main 重新校验并发送到已配置的 ASR。手动模式支持点击录音，以及按住用户选择的安全键位开始、松开结束；结果只填入输入框，不自动发送。默认模式为手动，默认按住说话键为 F8。

## 音频与表现边界

Renderer 只接收 Main 已校验的有限音频字节，使用 Web Audio 解码、排队和播放，并把本机播放音频的归一化 RMS 音量交给 Live2D 口型通道。口型使用噪声门、快开慢关与 0～1 限幅；停止或失败时立即归零。

模型清单必须显式声明 `controls.lipSync.mouthOpenParameter` 和有限 `gain`。没有声明、参数不存在或模型加载失败时不合成动作，声音与文字独立回退。Renderer 不能通过语音设置提交任意 Cubism 参数名、文件路径、命令或 IPC 频道。

## 服务与显示端边界

FPNF 的长期产品边界是本地角色服务，而不是设置页面。当前阶段由 Electron Main 承载对话、角色、记忆、密钥、网络与语音合成服务，并继续通过窄 IPC 与本机客户端通信；本里程碑不开放监听端口或通用 WebSocket 服务。

聊天客户端不再直接依赖 Live2D 控制器内部通道，只通过 `CharacterPresentationPort` 描述状态、情绪、动作和本机播放音量。内嵌 Pixi/Cubism Live2D 是第一个显示适配器。未来可以在另行授权的里程碑增加 Live2DViewerEX ExAPI 适配器，但 `.lpk` 继续由 ViewerEX 与 Steam 管理，FPNF 不解密、不复制，也不把 ViewerEX 变成基础聊天依赖。

设置界面只是服务的一个控制客户端。可选显示端失败时，文字聊天、记忆和角色资料仍由核心服务继续工作；同一时刻只允许一个音频播放主端，避免重复播放与口型冲突。
